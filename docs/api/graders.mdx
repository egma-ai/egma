A project grader connects one project to a [grader definition](/api/grader-library).
It owns the model choice, other settings, scope, and individual pass threshold.
Editing these values does not create a core version. Other projects keep their
own saved choices.

Egma automatically adds **Expected behaviors** to every project. It grades all
simulations and no production traces. You cannot remove it or change its scope.
You can change its language model and pass threshold.

## List project graders

**`GET /v1/graders`**

Use `projectId` when your credential does not select a project. The response
contains active `graders` and `nextPageToken`. Use that token as `pageToken` for
the next page.

```bash
curl "https://your-egma-instance/v1/graders?projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..."
```

Each grader contains:

| Field | Meaning |
| --- | --- |
| `id` | This project's stable `grd_` identity. |
| `projectId` | Owning project. |
| `graderDefinitionId` | The `grl_` definition identity. |
| `name`, `description` | Live definition metadata. |
| `owner`, `type`, `modalities` | Definition owner, execution type, and supported modalities. |
| `scopeEditable`, `removable` | Which project actions are allowed. |
| `scope` | Simulation selectors and production sampling. |
| `settings` | Complete saved values for the current parameter contract. |
| `passThreshold` | Normalized threshold from `0` through `1`. |
| `createdAt`, `updatedAt` | ISO 8601 timestamps. |

## Update settings, scope, or pass threshold

**`PATCH /v1/graders/{graderId}`**

Send one or more of `settings`, `scope`, or `passThreshold`. A supplied settings
object must be complete. Egma rejects missing keys, unknown keys, wrong types,
values outside the contract bounds, and unsupported model pairs.

```bash
curl -X PATCH \
  "https://your-egma-instance/v1/graders/grd_abc123?projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "settings": { "llm_provider": "openai", "llm_model": "gpt-4o-mini" },
    "passThreshold": 0.8
  }'
```

Read supported model pairs from `GET /v1/grader-form`. LLM settings contain
`llm_provider` and `llm_model`. Trusted code graders use their own contract; for
example, Response latency has the numeric `maximum_response_time_ms` setting.

Simulation scope accepts `all`, `test_suite`, or `test` selectors. Production
scope is `null` or an object with `samplePercent` from `1` through `100`:

```json
{
  "scope": {
    "simulations": [{ "kind": "test_suite", "id": "ste_abc123" }],
    "production": { "samplePercent": 10 }
  }
}
```

These edits apply to future work. Work already selected keeps its exact core,
model, other settings, scope result, and pass threshold, including delayed
execution and retries. A score passes its individual grader when
`score >= passThreshold`.

## Add or remove a grader

Use the [grader library](/api/grader-library) to use a shared definition, create
a custom grader, or clone a current LLM core.

**`DELETE /v1/graders/{graderId}`** removes an optional grader from future
selection. Its saved settings and existing grades remain available to the
system. Already selected work still executes. Expected behaviors cannot be
removed.
