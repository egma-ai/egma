title: "Start and follow complete test suite runs via API"

A run executes one complete test suite against one agent and one connection.
Egma resolves every current test in the suite inside the start transaction. It
creates one simulation for each test and persona combination.

The run stores the stable suite ID. Each simulation stores the exact test and
persona versions that it executes. A later test edit cannot change old evidence.

## Start a run

`POST /v1/runs`

<ParamField body="suiteId" type="string" required>
  The active `ste_…` suite ID. Egma runs every current test in this suite.
</ParamField>

<ParamField body="agentId" type="string" required>
  The `agt_…` agent ID.
</ParamField>

<ParamField body="connectionId" type="string" required>
  The `con_…` connection ID. It must belong to the selected agent.
</ParamField>

<ParamField body="idempotencyKey" type="string" required>
  A client-generated key for safe network recovery. Sending the same request
  with the same key returns the original run header instead of starting a
  second run. Using the key for different input is refused.
</ParamField>

<ParamField body="name" type="string">
  An optional display name for this run.
</ParamField>

<ParamField body="expectedTestVersions" type="object[]">
  An optional exact-set precondition for repository clients. Each item contains
  `testId` and `versionId`. The unordered set must exactly match the suite's
  current tests and versions. Egma checks it inside the start transaction. It
  is not a subset selector and is not stored on the run.
</ParamField>

An empty suite is refused before a run or simulation is created. Egma does not
accept a test picker, direct-test run, multi-suite run, or arbitrary version
list.

```bash
curl -X POST https://your-egma-host/v1/runs \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "suiteId": "ste_01JXMK8P2QN4R6S9T1UV3WX5Y",
    "agentId": "agt_01JXMK8P2QN4R6S9T1UV3WX5Y",
    "connectionId": "con_01JXMK8P2QN4R6S9T1UV3WX5Y",
    "idempotencyKey": "release-2026-08-21-northside",
    "name": "Northside release check"
  }'
```

The start response is a bounded run header. It does not embed every simulation.

## Run header fields

<ResponseField name="id" type="string">
  Stable run ID (`run_…`).
</ResponseField>

<ResponseField name="status" type="string">
  Current run status.
</ResponseField>

<ResponseField name="suiteId" type="string">
  Stable suite ID.
</ResponseField>

<ResponseField name="suiteName" type="string">
  The suite's current name. A rename also changes this value on old runs.
</ResponseField>

<ResponseField name="suiteDeleted" type="boolean">
  `true` when the source suite was permanently deleted. Display its name with
  `(deleted)`.
</ResponseField>

<ResponseField name="name" type="string | null">
  The optional run name, or `null`.
</ResponseField>

<ResponseField name="agentId" type="string">
  The selected agent.
</ResponseField>

<ResponseField name="connectionId" type="string">
  The selected connection.
</ResponseField>

<ResponseField name="expectedSimulationCount" type="integer">
  The number of test and persona combinations planned for this run.
</ResponseField>

<ResponseField name="completedCount" type="integer | null">
  Completed simulations when the run is settled.
</ResponseField>

<ResponseField name="failedCount" type="integer | null">
  Failed simulations when the run is settled.
</ResponseField>

<ResponseField name="canceledCount" type="integer | null">
  Canceled simulations when the run is settled.
</ResponseField>

<ResponseField name="verdict" type="string | null">
  Folded grader verdict when grading is complete.
</ResponseField>

<ResponseField name="resultsUrl" type="string">
  Signed-in browser URL for the run.
</ResponseField>

## List runs

`GET /v1/runs`

Returns bounded run headers:

```json
{
  "runs": [],
  "nextPageToken": null
}
```

<ParamField query="projectId" type="string">
  Project ID or name.
</ParamField>

<ParamField query="pageToken" type="string">
  The `run_…` cursor from the prior page.
</ParamField>

<ParamField query="pageSize" type="integer">
  Page size. The maximum is `200`.
</ParamField>

## Get a run

`GET /v1/runs/:runId`

Returns one bounded run header. It does not embed an unbounded simulation list.

## List a run's simulations

`GET /v1/runs/:runId/simulations`

Returns a bounded page:

```json
{
  "simulations": [],
  "nextPageToken": null
}
```

<ParamField query="pageToken" type="string">
  The `sim_…` cursor from the prior page.
</ParamField>

<ParamField query="pageSize" type="integer">
  Page size. The maximum is `200`.
</ParamField>

Each simulation names `testId`, `testVersionId`, `personaId`, and
`personaVersionId`. These are the exact identities and versions that ran.
Simulation status is `queued`, `claimed`, `running`, `completed`, `failed`, or
`canceled`. A grader verdict may separately be `passed`, `failed`, `skipped`, or
`errored`.

## Stream run events

`GET /v1/runs/:runId/events`

Use `after` as a sequence cursor. Save the last sequence you applied and send
it again after a disconnect.

<ParamField query="after" type="integer">
  Return events after this sequence number. Omit it for the first page.
</ParamField>

## Cancel a run

`POST /v1/runs/:runId/cancel`

Cancel every unfinished simulation in the run.

## Get a simulation recording

`GET /v1/simulations/:simulationId/recording`

Returns a short-lived playback URL when a completed voice simulation has a
recording. Chat simulations and calls that never connected have no recording.
