Production evidence reaches Egma two ways, and the agent is where the choice is
made.

**Pull is declared.** An agent may bind to one platform, hold that platform's
API key, and carry a single switch — **pull production calls**. While it is on,
Egma polls the platform for that agent's finished conversations.

**Push is observed.** A LiveKit agent sends spans to the Egma OTLP door with the
project API key from its own process. There is nothing to configure and nothing
to turn off: the stored evidence is the whole record. See
[Python SDK](/integrations/python-sdk).

The monitoring key is a **monitoring-only credential**. It is separate from
anything a connection holds for a simulation, so a customer who chat-tests and
pull-monitors the same Retell account enters the key twice, once per job. Egma
seals it exactly as it seals a connection credential and never gives it back.

All routes on this page use the normal Egma authentication rules. Pass the
project identifier in the `projectId` query parameter. A project-scoped API key
can omit it when the key already names the project.

## Discover Retell voice agents

**`POST /v1/monitoring/retell/discover`**

Validates a Retell API key and lists the account's voice agents, so a person can
pick the one an Egma agent runs as. Egma stores nothing here.

<ParamField body="apiKey" type="string" required>
  A Retell API key with Agent Read permission.
</ParamField>

<ResponseField name="agents" type="array">
  Voice-agent identities, each with `id` and `name`, sorted by name.
</ResponseField>

```bash
curl -X POST "https://your-egma-host/v1/monitoring/retell/discover?projectId=prj_abc123" \
  -H "Authorization: Bearer $EGMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"apiKey":"key_live_..."}'
```

## Turn pull on

**`PUT /v1/agents/{agentId}/production-pull`**

Binds the agent to its platform, seals the monitoring key on the agent's own
row, and opens a 30-day historical import. Sending it again re-arms that import
from the current instant.

Egma checks the key against both permissions polling needs — reading the
account's agents and reading its call history — **before** anything is sealed, so
a key that can do only one of them is refused with the permission it is missing.

<ParamField body="agentPlatform" type="string" required>
  `retell`. Egma pulls from Retell today; a LiveKit agent pushes instead.
</ParamField>

<ParamField body="platformAgentId" type="string" required>
  The agent's own identifier on its platform, from the discovery route above.
</ParamField>

<ParamField body="apiKey" type="string" required>
  The platform API key Egma pulls this agent's production calls with.
</ParamField>

<ResponseField name="pullSwitch" type="object">
  `agentId`, `agentPlatform`, `platformAgentId`, `monitoringKeyHint`, and
  `pullProductionCalls`. The key itself is never in a response.
</ResponseField>

At most one agent in a project may pull for a given platform agent. A second
agent naming the same `platformAgentId` while the first is switched on is
refused with `422`, so two Egma agents can never poll one platform agent twice.

```bash
curl -X PUT "https://your-egma-host/v1/agents/agt_abc123/production-pull?projectId=prj_abc123" \
  -H "Authorization: Bearer $EGMA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"agentPlatform":"retell","platformAgentId":"agent_abc","apiKey":"key_live_..."}'
```

## Turn pull off

**`DELETE /v1/agents/{agentId}/production-pull`**

Stops the polling. Everything already stored stays where it is, and so does the
agent's binding, its sealed key, and the cursor its reading had reached — so
turning it back on resumes rather than re-reading history Egma already holds.

<ResponseField name="pullSwitch" type="object">
  The same object as above, with `pullProductionCalls: false`.
</ResponseField>

```bash
curl -X DELETE "https://your-egma-host/v1/agents/agt_abc123/production-pull?projectId=prj_abc123" \
  -H "Authorization: Bearer $EGMA_API_KEY"
```

## Refusals

| Status | When |
|---|---|
| `403` | The role cannot change monitoring. Checked before any request to the platform. |
| `404` | No active agent with that id in this project. |
| `422` | The key is rejected, lacks call-history permission, names an agent the account does not run, or another agent is already pulling for that platform agent. |
| `503` | The platform did not answer the setup check. |

## Reading what arrived

Production conversations are read through the trace routes, not here. See
