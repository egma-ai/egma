Production evidence reaches Egma in one of two ways.

**Pull** is Egma asking the agent platform for the calls it has finished. It is
a per-agent choice: an agent binds to its platform, holds that platform's API
key, and one switch — **pull production calls** — turns polling on. Retell is
the platform Egma pulls from today.

**Push** is your own agent process sending its spans to Egma. It needs no
switch and no configuration on this page: set `EGMA_URL` and a project-scoped
`EGMA_API_KEY` in the agent, call `monitor_livekit(ctx)` before
`AgentSession.start`, and the conversations appear on the Monitoring page. See
[Egma Python SDK](/integrations/python-sdk).

There is no monitoring configuration object. The switch on the agent is the
only stored monitoring choice, and an agent's fields are documented with
[Agents](/api/agents).

All routes on this page use the normal Egma authentication rules. Pass the
project identifier in the `projectId` query parameter. A project-scoped API key
can omit it when the key already names the project.

## Discover Retell voice agents

**`POST /v1/monitoring/retell/discover`**

Checks one Retell API key and returns only voice agents, together with what
this project already knows about each one. This request does not save the key.

<ParamField body="apiKey" type="string" required>
  Retell platform API key with Agent Read permission.
</ParamField>

<ResponseField name="agents" type="array">
  Voice-agent choices, sorted by name.
</ResponseField>

Each choice has these fields:

| Field | Meaning |
|---|---|
| `id` | Retell's own agent id. |
| `name` | Retell's current name for the agent. |
| `registeredAgentId` | The Egma agent already bound to it, or `null`. |
| `registeredAgentName` | That agent's name, or `null`. |
| `pullProductionCalls` | Whether that Egma agent already pulls its calls. |

```bash
curl -X POST \
  "https://your-egma-host/v1/monitoring/retell/discover?projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..." \
  -H "Content-Type: application/json" \
  -d '{ "apiKey": "key_live_..." }'
```

## Start pulling production calls

**`POST /v1/monitoring/start`**

Seals the Retell key onto every agent this request names, turns each agent's
pull switch on, and starts a fixed 30-day import for each. After the import
finishes, Egma checks for new finished conversations about every 30 seconds.

<ParamField body="agentPlatform" type="string" required>
  `retell`. Push platforms need no start request.
</ParamField>

<ParamField body="apiKey" type="string" required>
  Retell platform API key. Egma seals it on each agent and never returns it.
  It needs Retell Monitor or History Read permission as well as Agent Read.
</ParamField>

<ParamField body="watch" type="object[]" required>
  One entry per Retell agent to watch, shaped as
  `{ platformAgentId, name?, agentId? }`.
</ParamField>

Each `watch` entry resolves to one Egma agent:

- With `agentId`, that agent is bound to `platformAgentId` and switched on.
- Without `agentId`, Egma looks for an agent in the project already bound to
  `platformAgentId` and updates it. When none exists, Egma registers a new
  agent under `name` and switches it on. Watching a Retell agent Egma does not
  know means registering it.

<ResponseField name="watching" type="array">
  One entry per started agent, shaped as
  `{ agentId, agentName, platformAgentId, created, pullProductionCalls }`.
  `created` is `true` when this request registered the agent.
</ResponseField>

One Egma agent watches one Retell agent. A request that would put a second
switched-on agent on the same Retell agent returns `409 conflict` and names the
agent already watching it. Turn that agent's switch off first, or start
monitoring from it instead.

The key is a monitoring credential and is kept apart from any key a connection
holds for simulations. Egma asks for it here even when a connection on the same
agent already stores one for the same Retell account.

```bash
curl -X POST \
  "https://your-egma-host/v1/monitoring/start?projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "agentPlatform": "retell",
    "apiKey": "key_live_...",
    "watch": [
      { "platformAgentId": "agent_abc123", "agentId": "agt_abc123" },
      { "platformAgentId": "agent_def456", "name": "Billing" }
    ]
  }'
```

## Stop pulling production calls

**`POST /v1/monitoring/agents/:agentId/stop`**

Turns one agent's pull switch off. Egma stops asking the platform and keeps
everything it already has: the stored production conversations, the agent's
platform binding, its sealed key, and its import progress. Starting again
continues from where it stopped.

<ParamField path="agentId" type="string" required>
  Egma agent id.
</ParamField>

<ResponseField name="monitoring" type="object">
  `{ agentId, pullProductionCalls, agentPlatform, platformAgentId, monitoringApiKeyHint, lastReceivedAt }`.
</ResponseField>

```bash
curl -X POST \
  "https://your-egma-host/v1/monitoring/agents/agt_abc123/stop?projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..."
```

## Retry one Retell import

**`POST /v1/monitoring/retell/failures/:failureId/replay`**

Retries the exact Retell call named by one open import failure. It reads the
call directly, so it still works after that call is outside the normal 30-day
list window. The production claim prevents a successful retry from creating a
second production conversation.

<ParamField path="failureId" type="string" required>
  Import failure id.
</ParamField>

<ResponseField name="monitoringImportFailure" type="object">
  `{ id, status: "resolved" }` after a successful retry.
</ResponseField>

<ResponseField name="trace" type="object">
  `{ id, write }`, where `write` is `written` or `already`.
</ResponseField>

A retry returns `409 conflict` when another retry owns the failure or Retell
still cannot supply a complete conversation. It returns `429` when Retell rate
limits it, and also when the agent is waiting out its own retry delay after
recent failures — the message says when that delay ends. A temporary provider
failure returns `503`.
