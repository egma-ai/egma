---

An agent is Egma's stable record of the agent you test. A **connection** is a
separate record that tells the simulator how to reach it. One agent can have
several connections, and each connection links back through `agentId`.

A connection states its agent platform, connection type, access variant, and
modality. Egma derives its product label and topology from those facts. The
agent platform says where the agent runs; the connection type selects the
simulator adapter. For example, a Retell or LiveKit worker can use the
same platform-independent `phone_number` connection type.

Registering with an inline connection is retry-safe. The `result` field says
whether Egma created an agent, reused it, or added another connection.
Credentials are sealed before storage. Only a safe hint comes back, so an API
response cannot expose the stored secret.

---

## List supported simulation connections

`GET /v1/connection-options`

Read this catalog before drawing a connection form. The server returns each
supported combination of agent platform, connection type, access variant, and
modality. It also returns the derived product label, required configuration
fields, credential rule, and whether this deployment has a simulator adapter.

<ResponseField name="items" type="array">
  Supported simulation connection options. Each item includes
  `agentPlatform`, `agentPlatformLabel`, `connectionType`,
  `accessVariant`, `accessVariantLabel`, `modality`, `productLabel`,
  `topology`, `simulatorAdapter`, `fields`,
  `credentialRule`, `credentialHelp`, and `credentialFields`.
</ResponseField>

The catalog contains safe form metadata only. It never returns a validation
function or a stored credential.

```bash
curl "https://your-egma-host/v1/connection-options" \
  -H "Authorization: Bearer <api-key>"
```

## Register an agent

`POST /v1/agents`

Register a new Agent identity. Leave `connection` out to create the identity by itself, as `egma agent register` does. API clients may also attach the first Connection in the same request. When a Connection is present, both rows are written in one transaction, so a payload the registry rejects leaves no partial Agent behind.

The `result` field in the response tells you exactly what happened:

| Value | Meaning |
|---|---|
| `created` | A new Agent was written. If the request supplied a Connection, that Connection was also written. |
| `reused` | An agent with this provider id already existed; nothing was written. |
| `connection_added` | The agent already existed; a new connection was attached to it. |

`201 Created` is returned for `created` and `connection_added`. `200 OK` is returned for `reused`.

### Request body

<ParamField body="name" type="string">
  Display name for the agent. Required unless you want Egma to pick a numbered default. Must be unique within the project.
</ParamField>

<ParamField body="agentPlatform" type="string" required>
  The platform that runs this agent. Current values are `retell` and `livekit`.
</ParamField>

<ParamField query="projectId" type="string">
  Project id or name to write this agent into. Defaults to the project your API key belongs to. In a single-project organization you never need this field.
</ParamField>

<ParamField body="connection" type="object">
  The first connection to attach. Leave this out to register a bare agent and add connections later with `POST /v1/agents/:agentId/connections`.

  <Expandable title="connection fields">
    <ParamField body="agentPlatform" type="string | null" required>
      Which platform this combination is for. Current values are `retell`,
      `livekit`, or `null`.

      A connection stores no platform of its own. Some connection types reach
      exactly one platform — `retell_text_mode` and `retell_web_call` reach
      Retell, `livekit_room` reaches LiveKit — and for those the type answers
      and this field
      only selects the combination to check. `phone_number` reaches any
      platform, so a phone connection belongs to whichever platform its **agent**
      declares.

      Send `null` to let the agent answer. Naming a platform that differs from
      the one the agent is bound to is refused with `422`, because Egma would
      otherwise have to store the connection under a platform you did not
      choose.
    </ParamField>

    <ParamField body="connectionType" type="string" required>
      How the simulator reaches the agent. Current values are
      `retell_text_mode`, `retell_web_call`, `phone_number`, and
      `livekit_room`.
    </ParamField>

    <ParamField body="accessVariant" type="string" required>
      How Egma gets access to that connection type. Use
      `GET /v1/connection-options` for the current supported combinations and
      their fields.
    </ParamField>

    <ParamField body="modality" type="string" required>
      `chat` or `voice`, as required by the selected connection type.
    </ParamField>

    <ParamField body="name" type="string">
      Display name for this connection. Defaults to a numbered name if omitted.
    </ParamField>

    <ParamField body="environment" type="string">
      Optional environment label, e.g. `staging` or `production`.
    </ParamField>

    <ParamField body="config" type="object" required>
      Access-variant configuration. Examples include
      `{ "retellAgentId": "<retell_agent_id>" }`,
      `{ "phoneNumber": "+14155550111" }`, and
      `{ "url": "wss://…", "agentName": "<optional>" }`.
    </ParamField>

    <ParamField body="credentials" type="object">
      Credentials required by the selected access variant. They are sealed
      before storage and never returned in full. A public phone-number variant
      forbids connection credentials.
    </ParamField>
  </Expandable>
</ParamField>

### Response fields

<ResponseField name="result" type="string">
  One of `created`, `reused`, or `connection_added`.
</ResponseField>

<ResponseField name="agent" type="object">
  The agent record.

  <Expandable title="agent fields">
    <ResponseField name="id" type="string">Unique agent identifier (`agt_…`).</ResponseField>
    <ResponseField name="projectId" type="string">The project this agent belongs to.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="agentPlatform" type="string">The platform that runs this agent (`retell` or `livekit`).</ResponseField>
    <ResponseField name="platformAgentId" type="string | null">That platform's own identifier for this agent, or `null`.</ResponseField>
    <ResponseField name="retellModality" type="string | null">`voice` or `chat` for a Retell agent after Egma confirms its provider identity, or `null` when it does not apply or is not known yet.</ResponseField>
    <ResponseField name="monitoringKeyPresent" type="boolean">Whether a platform key is stored for pulling this agent's production conversations.</ResponseField>
    <ResponseField name="monitoringApiKeyHint" type="string | null">Last four characters of that key, or `null`. Egma never returns the key itself.</ResponseField>
    <ResponseField name="pullProductionCalls" type="boolean">Whether Egma pulls this agent's production conversations from its platform. Turn it on with [Start pulling production calls](/api/monitoring).</ResponseField>
    <ResponseField name="monitoringConfigured" type="boolean">Whether pull monitoring has ever been started for this agent. This remains `true` after monitoring is stopped.</ResponseField>
    <ResponseField name="archived" type="boolean">Whether the agent is archived.</ResponseField>
    <ResponseField name="archivedAt" type="string | null">ISO 8601 timestamp, or `null` while the agent is active.</ResponseField>
    <ResponseField name="createdAt" type="string">ISO 8601 timestamp.</ResponseField>
    <ResponseField name="updatedAt" type="string">ISO 8601 timestamp.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="connection" type="object">
  The Connection that was created or reused. Absent when the request registered only an Agent identity and whenever no Connection was returned.

  <Expandable title="connection fields">
    <ResponseField name="id" type="string">Unique connection identifier.</ResponseField>
    <ResponseField name="agentId" type="string">The agent this connection belongs to.</ResponseField>
    <ResponseField name="projectId" type="string">The project this connection belongs to.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="agentPlatform" type="string">The platform this connection reaches. Derived, never stored: the connection type answers where it reaches exactly one platform, otherwise the agent's declared platform answers.</ResponseField>
    <ResponseField name="connectionType" type="string">The path the simulator uses.</ResponseField>
    <ResponseField name="accessVariant" type="string">How Egma gets access to that path.</ResponseField>
    <ResponseField name="modality" type="string">`chat` or `voice`.</ResponseField>
    <ResponseField name="productLabel" type="string">Display text derived from the supported combination, using the same platform as `agentPlatform` above.</ResponseField>
    <ResponseField name="topology" type="string">Derived execution detail that indicates who initiates the connection.</ResponseField>
    <ResponseField name="environment" type="string | null">Environment label, or `null`.</ResponseField>
    <ResponseField name="config" type="object">Safe configuration for the access variant.</ResponseField>
    <ResponseField name="credentialPresent" type="boolean">Whether this connection stores a sealed credential.</ResponseField>
    <ResponseField name="credentialsHint" type="string | null">Safe hint for the stored credential, or `null`.</ResponseField>
    <ResponseField name="createdAt" type="string">ISO 8601 timestamp.</ResponseField>
    <ResponseField name="updatedAt" type="string">ISO 8601 timestamp.</ResponseField>
  </Expandable>
</ResponseField>

### Example — register a Retell voice agent for text-mode simulations

```bash
curl -X POST https://your-egma-host/v1/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "front-desk",
    "agentPlatform": "retell",
    "connection": {
      "agentPlatform": "retell",
      "connectionType": "retell_text_mode",
      "accessVariant": "retell_text_mode.api_key",
      "modality": "chat",
      "config": { "retellAgentId": "retell_agent_abc123" },
      "credentials": { "apiKey": "retell_sk_…" }
    }
  }'
```

### Example — register a LiveKit room connection

```bash
curl -X POST https://your-egma-host/v1/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-bot",
    "agentPlatform": "livekit",
    "connection": {
      "agentPlatform": "livekit",
      "connectionType": "livekit_room",
      "accessVariant": "livekit_room.project_credentials",
      "modality": "voice",
      "config": {
        "url": "wss://my-livekit.example.com",
        "agentName": "support-agent"
      },
      "credentials": {
        "apiKey": "livekit_api_key",
        "apiSecret": "livekit_api_secret"
      }
    }
  }'
```

## List agents

`GET /v1/agents`

Return a paginated list of agents your credential can reach, ordered newest first. Each agent carries the connections currently attached to it, so one request tells you which agents Egma can reach and how. Filter by project with `?projectId`. Paginate using the `nextPageToken` value from the previous page.

### Query parameters

<ParamField query="projectId" type="string">
  Filter to a specific project by id or name. Omit to list agents across all projects your key can read.
</ParamField>

<ParamField query="pageToken" type="string">
  The `nextPageToken` value from the previous page. Omit to start from the newest agent.
</ParamField>

### Response fields

<ResponseField name="agents" type="array">
  Array of agent objects. Each has the same shape as the `agent` field in the registration response, plus a `connections` array.

  <Expandable title="listed agent fields">
    <ResponseField name="connections" type="array">
      The connections currently attached to that agent, each with the same shape as the `connection` field in the registration response. An agent with no connection carries an empty array. Archived connections are not listed here; read that one agent with `GET /v1/agents/:agentId?archived=true` for those. (On this endpoint, `?archived=true` asks for archived *agents*.)
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="nextPageToken" type="string | null">
  Pass this as `?pageToken` to fetch the next page. `null` means you are on the last page.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/v1/agents?projectId=my-project&pageToken=agt_prev" \
  -H "Authorization: Bearer <api-key>"
```

## Get an agent

`GET /v1/agents/:agentId`

Retrieve a single agent and all of its connections. An agent you cannot see answers the same `not_found` sentence as an id that was never minted.

### Path parameters

<ParamField path="agentId" type="string" required>
  The `agt_…` identifier of the agent.
</ParamField>

### Response fields

<ResponseField name="agent" type="object">
  The agent record (same shape as in registration).
</ResponseField>

<ResponseField name="connections" type="array">
  All connections currently attached to this agent. Each entry has the same shape as the `connection` field in the registration response.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/v1/agents/agt_01abc" \
  -H "Authorization: Bearer <api-key>"
```

## Add a connection

`POST /v1/agents/:agentId/connections`

Attach another simulation connection to an existing agent. The request body is identical in shape to the `connection` object on registration. Returns `201 Created` with the new connection.

### Path parameters

<ParamField path="agentId" type="string" required>
  The `agt_…` identifier of the agent to attach the connection to.
</ParamField>

### Request body

Same fields as the `connection` object on `POST /v1/agents`. The agent
platform, connection type, access variant, and modality must name one supported
combination from `GET /v1/connection-options`.

### Response fields

<ResponseField name="connection" type="object">
  The newly created connection record (same shape as the `connection` field in the registration response).
</ResponseField>

### Example

```bash
curl -X POST "https://your-egma-host/v1/agents/agt_01abc/connections" \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "agentPlatform": "retell",
    "connectionType": "phone_number",
    "accessVariant": "phone_number.public_e164",
    "modality": "voice",
    "environment": "staging",
    "config": { "phoneNumber": "+14155550111" }
  }'
```
