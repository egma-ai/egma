An agent is Egma's stable record of the agent you test. A **connection** is a
separate record that tells the simulator how to reach it. One agent can have
several connections, and each connection links back through `agent_id`.

A connection states its agent platform, connection kind, access variant, and
modality. Egma derives its product label and topology from those facts. The
agent platform says where the agent runs; the connection kind selects the
simulator adapter. For example, a Retell or LiveKit Agents worker can use the
same platform-independent `phone_number` connection kind.

Registering with an inline connection is retry-safe. The `result` field says
whether Egma created an agent, reused it, or added another connection.
Credentials are sealed before storage. Only a safe hint comes back, so an API
response cannot expose the stored secret.

---

## List supported simulation connections

`GET /api/connection-options`

Read this catalog before drawing a connection form. The server returns each
supported combination of agent platform, connection kind, access variant, and
modality. It also returns the derived product label, required configuration
fields, credential rule, and whether this deployment has a simulator adapter
and capability discovery.

<ResponseField name="items" type="array">
  Supported simulation connection options. Each item includes
  `agent_platform`, `agent_platform_label`, `connection_kind`,
  `access_variant`, `access_variant_label`, `modality`, `product_label`,
  `topology`, `simulator_adapter`, `capability_discovery`, `fields`,
  `credential_rule`, `credential_help`, and `credential_fields`.
</ResponseField>

The catalog contains safe form metadata only. It never returns a validation
function or a stored credential.

```bash
curl "https://your-egma-host/api/connection-options" \
  -H "Authorization: Bearer <api-key>"
```

## Register an agent

`POST /api/agents`

Register a new agent and, optionally, attach the first connection to it in the same request. Both the agent row and the connection row are written in one transaction, so a connection payload the registry rejects leaves no partial agent behind.

The `result` field in the response tells you exactly what happened:

| Value | Meaning |
|---|---|
| `created` | A new agent and a new connection were written. |
| `reused` | An agent with this provider id already existed; nothing was written. |
| `connection_added` | The agent already existed; a new connection was attached to it. |

`201 Created` is returned for `created` and `connection_added`. `200 OK` is returned for `reused`.

### Request body

<ParamField body="name" type="string">
  Display name for the agent. Required unless you want Egma to pick a numbered default. Must be unique within the project.
</ParamField>

<ParamField body="description" type="string">
  Optional free-text description.
</ParamField>

<ParamField body="project" type="string">
  Project id or name to write this agent into. Defaults to the project your API key belongs to. In a single-project organization you never need this field.
</ParamField>

<ParamField body="connection" type="object">
  The first connection to attach. Leave this out to register a bare agent and add connections later with `POST /api/agents/:agentId/connections`.

  <Expandable title="connection fields">
    <ParamField body="agent_platform" type="string | null" required>
      Where the agent runs. Current values are `retell`, `livekit_agents`, or
      `null` when the platform is unknown or does not matter to this path.
    </ParamField>

    <ParamField body="connection_kind" type="string" required>
      How the simulator reaches the agent. Current values are
      `retell_chat_api`, `phone_number`, and `livekit_room`.
    </ParamField>

    <ParamField body="access_variant" type="string" required>
      How Egma gets access to that connection kind. Use
      `GET /api/connection-options` for the current supported combinations and
      their fields.
    </ParamField>

    <ParamField body="modality" type="string" required>
      `chat` or `voice`, as required by the selected connection kind.
    </ParamField>

    <ParamField body="name" type="string">
      Display name for this connection. Defaults to a numbered name if omitted.
    </ParamField>

    <ParamField body="environment" type="string">
      Optional environment label, e.g. `staging` or `production`.
    </ParamField>

    <ParamField body="config" type="object" required>
      Access-variant configuration. Examples include
      `{ "retellAgentId": "<retell_agent_id>" }`,
      `{ "phoneNumber": "+14155550111" }`, and
      `{ "url": "wss://…", "agentName": "<optional>" }`.
    </ParamField>

    <ParamField body="credentials" type="object">
      Credentials required by the selected access variant. They are sealed
      before storage and never returned in full. A public phone-number variant
      forbids connection credentials.
    </ParamField>
  </Expandable>
</ParamField>

### Response fields

<ResponseField name="result" type="string">
  One of `created`, `reused`, or `connection_added`.
</ResponseField>

<ResponseField name="agent" type="object">
  The agent record.

  <Expandable title="agent fields">
    <ResponseField name="id" type="string">Unique agent identifier (`agt_…`).</ResponseField>
    <ResponseField name="project_id" type="string">The project this agent belongs to.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="description" type="string | null">Free-text description, or `null`.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 timestamp.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 timestamp.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="connection" type="object">
  The connection that was created or reused. Absent when `result` is `reused` and no new connection was written.

  <Expandable title="connection fields">
    <ResponseField name="id" type="string">Unique connection identifier.</ResponseField>
    <ResponseField name="agent_id" type="string">The agent this connection belongs to.</ResponseField>
    <ResponseField name="project_id" type="string">The project this connection belongs to.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="agent_platform" type="string | null">The agent platform recorded for this connection.</ResponseField>
    <ResponseField name="connection_kind" type="string">The path the simulator uses.</ResponseField>
    <ResponseField name="access_variant" type="string">How Egma gets access to that path.</ResponseField>
    <ResponseField name="modality" type="string">`chat` or `voice`.</ResponseField>
    <ResponseField name="product_label" type="string">Display text derived from the supported combination.</ResponseField>
    <ResponseField name="topology" type="string">Derived execution detail that indicates who initiates the connection.</ResponseField>
    <ResponseField name="environment" type="string | null">Environment label, or `null`.</ResponseField>
    <ResponseField name="config" type="object">Safe configuration for the access variant.</ResponseField>
    <ResponseField name="credential_present" type="boolean">Whether this connection stores a sealed credential.</ResponseField>
    <ResponseField name="credentials_hint" type="string | null">Safe hint for the stored credential, or `null`.</ResponseField>
    <ResponseField name="capabilities" type="object">Provider capabilities detected at registration time.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 timestamp.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 timestamp.</ResponseField>
  </Expandable>
</ResponseField>

### Example — register a Retell chat agent

```bash
curl -X POST https://your-egma-host/api/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "front-desk",
    "connection": {
      "agent_platform": "retell",
      "connection_kind": "retell_chat_api",
      "access_variant": "retell_chat_api.api_key",
      "modality": "chat",
      "config": { "retellAgentId": "retell_agent_abc123" },
      "credentials": { "apiKey": "retell_sk_…" }
    }
  }'
```

### Example — register a LiveKit room connection

```bash
curl -X POST https://your-egma-host/api/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-bot",
    "connection": {
      "agent_platform": "livekit_agents",
      "connection_kind": "livekit_room",
      "access_variant": "livekit_room.project_credentials",
      "modality": "voice",
      "config": {
        "url": "wss://my-livekit.example.com",
        "agentName": "support-agent"
      },
      "credentials": {
        "apiKey": "livekit_api_key",
        "apiSecret": "livekit_api_secret"
      }
    }
  }'
```

## List agents

`GET /api/agents`

Return a paginated list of agents your credential can reach, ordered newest first. Filter by project with `?project`. Paginate using the `next_cursor` value from the previous page.

### Query parameters

<ParamField query="project" type="string">
  Filter to a specific project by id or name. Omit to list agents across all projects your key can read.
</ParamField>

<ParamField query="cursor" type="string">
  The `next_cursor` value from the previous page. Omit to start from the newest agent.
</ParamField>

### Response fields

<ResponseField name="items" type="array">
  Array of agent objects. Each has the same shape as the `agent` field in the registration response.
</ResponseField>

<ResponseField name="next_cursor" type="string | null">
  Pass this as `?cursor` to fetch the next page. `null` means you are on the last page.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/api/agents?project=my-project&cursor=agt_prev" \
  -H "Authorization: Bearer <api-key>"
```

## Get an agent

`GET /api/agents/:agentId`

Retrieve a single agent and all of its connections. An agent you cannot see answers the same `not_found` sentence as an id that was never minted.

### Path parameters

<ParamField path="agentId" type="string" required>
  The `agt_…` identifier of the agent.
</ParamField>

### Response fields

<ResponseField name="agent" type="object">
  The agent record (same shape as in registration).
</ResponseField>

<ResponseField name="connections" type="array">
  All connections currently attached to this agent. Each entry has the same shape as the `connection` field in the registration response.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/api/agents/agt_01abc" \
  -H "Authorization: Bearer <api-key>"
```

## Add a connection

`POST /api/agents/:agentId/connections`

Attach another simulation connection to an existing agent. The request body is identical in shape to the `connection` object on registration. Returns `201 Created` with the new connection.

### Path parameters

<ParamField path="agentId" type="string" required>
  The `agt_…` identifier of the agent to attach the connection to.
</ParamField>

### Request body

Same fields as the `connection` object on `POST /api/agents`. The agent
platform, connection kind, access variant, and modality must name one supported
combination from `GET /api/connection-options`.

### Response fields

<ResponseField name="connection" type="object">
  The newly created connection record (same shape as the `connection` field in the registration response).
</ResponseField>

### Example

```bash
curl -X POST "https://your-egma-host/api/agents/agt_01abc/connections" \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "agent_platform": "retell",
    "connection_kind": "phone_number",
    "access_variant": "phone_number.public_e164",
    "modality": "voice",
    "environment": "staging",
    "config": { "phoneNumber": "+14155550111" }
  }'
```
