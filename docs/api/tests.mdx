sidebarTitle: "Tests"
description: "Create, edit, and list simulation test scenarios. Versioned content stays immutable, and optimistic locking prevents silent overwrites."
---

Tests are the simulation scenarios Egma runs against your agents. Each test holds a natural-language scenario, a list of expected behaviors the agent should exhibit, the personas who call, and the world the test carries: its `mockTools` and its `env`. Saving versioned content mints a new immutable **test version** — a frozen record identified by its own `versionId`. A name-only edit does not mint a version. Simulations always execute against exact version IDs, so a later test edit never changes an earlier result.

An edit to versioned content requires the `expectedVersionId` you last read. If
another writer has moved the test forward, Egma refuses with `409 Conflict` and
tells you both version IDs. A name or description edit does not mint a test
version. You may send the last `revision` as `expectedRevision` to protect
those identity fields from a concurrent edit.

---

## Create a test

`POST /v1/tests`

Create a new test inside one active suite. Returns `201 Created` with the full
test object, including the first `versionId` to use in future edits.

### Request body

<ParamField body="name" type="string" required>
  Display name for the test.
</ParamField>

<ParamField body="suiteId" type="string" required>
  The stable `ste_…` ID of the suite that will contain this test. The test
  cannot move to another suite later.
</ParamField>

<ParamField body="scenario" type="string" required>
  A natural-language description of the situation the simulated caller is in, e.g. `"A customer wants to reschedule a dentist appointment."`.
</ParamField>

<ParamField body="expectedBehaviors" type="string[]" required>
  The behaviors the agent must exhibit, as plain sentences, e.g. `["confirms the new time before hanging up", "does not ask for the same information twice"]`. The `{"behavior", "priority"}` object shape is no longer accepted.
</ParamField>

<ParamField body="personas" type="string[]" required>
  Personas to assign to this test, by name or `prs_…` identifier. Each entry calls in separately when the test is run. A test says who calls, so at least one is required: an omitted or empty list is refused.
</ParamField>

<ParamField body="mockTools" type="object[]">
  The tools this test answers for itself. Egma mocks exactly the tools this list
  names; every other tool the agent calls runs for real. A test that names none
  runs against your real tools.

  <Expandable title="mock tool fields">
    <ParamField body="tool" type="string" required>
      The tool's name, exactly as the agent registers it. Matching is by name
      only, so each tool is named at most once in the list.
    </ParamField>
    <ParamField body="answer" type="any">
      What the tool returns: any JSON value. Send either `answer` or `error`,
      never both and never neither.
    </ParamField>
    <ParamField body="error" type="string">
      The failure the tool raises, written as text. This is how a test forces
      the failure branch.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="env" type="object | null">
  The world the test is conducted in: the data the call starts with. At most
  two keys, each in its own platform's spelling. Send `null`, or leave the
  field out, for a test that names none.

  <Expandable title="env fields">
    <ParamField body="retell_dynamic_variables" type="object">
      The values Retell substitutes into the agent's prompt and tool
      configuration for this call, as an object of text values, such as
      `{"caller_name": "Margaret"}`. Every value is text. A name beginning
      `egma_` is reserved and refused.
    </ParamField>
    <ParamField body="job_dispatch_metadata" type="object">
      The JSON object your LiveKit worker reads at `ctx.job.metadata`, such as
      `{"tenant": "acme"}`. Egma writes it to the dispatch as one compact JSON
      string, byte for byte.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField query="projectId" type="string">
  Project id or name to create the test in. Defaults to the project your API key belongs to. In a single-project organization you never need this field.
</ParamField>

### Response fields

<ResponseField name="id" type="string">
  Unique test identifier (`tst_…`).
</ResponseField>

<ResponseField name="name" type="string">
  Display name.
</ResponseField>

<ResponseField name="suiteId" type="string">
  The stable ID of the test's permanent suite (`ste_…`).
</ResponseField>

<ResponseField name="version" type="integer">
  Monotonically increasing version number. Starts at `1`.
</ResponseField>

<ResponseField name="versionId" type="string">
  The immutable id of this version (`tstv_…`). Supply this as
  `expectedVersionId` when editing versioned content.
</ResponseField>

<ResponseField name="revision" type="string">
  The current identity revision (`rev_…`). You may supply this as
  `expectedRevision` when editing the name or description.
</ResponseField>

<ResponseField name="scenario" type="string">
  The scenario text.
</ResponseField>

<ResponseField name="expectedBehaviors" type="string[]">
  The list of expected behaviors.
</ResponseField>

<ResponseField name="personas" type="object[]">
  Personas attached to this test.

  <Expandable title="persona fields">
    <ResponseField name="id" type="string">Persona identifier (`prs_…`).</ResponseField>
    <ResponseField name="name" type="string">Persona display name.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="mockTools" type="object[]">
  The tools this test answers for itself. Each entry has `tool` and exactly one
  of `answer` and `error`. Always present; an empty array means the test mocks
  nothing.
</ResponseField>

<ResponseField name="env" type="object | null">
  The world the test carries, with the keys it named. Always present; `null`
  means the test names none.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp.
</ResponseField>

<ResponseField name="updatedAt" type="string">
  ISO 8601 timestamp.
</ResponseField>

### Example

```bash
curl -X POST https://your-egma-host/v1/tests \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "suiteId": "ste_01JXMK8P2QN4R6S9T1UV3WX5Y",
    "name": "reschedule appointment",
    "scenario": "A patient wants to move their 9 a.m. appointment to the afternoon.",
    "expectedBehaviors": [
      "confirms the new time before ending the call",
      "does not ask for the same information twice"
    ],
    "personas": ["impatient-caller"],
    "mockTools": [
      { "tool": "check_availability", "answer": { "slots": ["2 p.m.", "4 p.m."] } },
      { "tool": "charge_card", "error": "the payment processor is unreachable" }
    ],
    "env": {
      "retell_dynamic_variables": { "caller_name": "Margaret" },
      "job_dispatch_metadata": { "tenant": "acme" }
    }
  }'
```

The agent's other tools — `send_confirmation`, whatever else it registers — run
for real on this test, because the list does not name them.

## Edit a test

`PATCH /v1/tests/:testId`

Update one or more fields of an existing test. Supply `expectedVersionId` when
the request changes the scenario, expected behaviors, personas, mock tools, or
env. If the test has moved on since you read it, Egma returns `409 Conflict`
with both version IDs.

Fields you omit are kept as-is. Omitting `personas` leaves the current persona list unchanged; an explicit empty array (`[]`) is refused, because a test always says who calls. Omitting `mockTools` or `env` leaves each as it is; `"mockTools": []` mocks nothing, and `"env": null` clears the env.

Sending content byte-identical to the current version mints no new version and
returns the current version unchanged. Changing only the `name` or `description`
also mints no new test version because those fields describe the test identity.

### Path parameters

<ParamField path="testId" type="string" required>
  The `tst_…` identifier of the test to edit.
</ParamField>

### Request body

<ParamField body="expectedVersionId" type="string">
  The `versionId` you last read. Required when changing versioned content. The
  edit is refused if the test has moved on.
</ParamField>

<ParamField body="expectedRevision" type="string">
  The `revision` you last read. Optional protection for name and description
  edits. A stale value is refused with an identity conflict.
</ParamField>

<ParamField body="name" type="string">
  New display name.
</ParamField>

<ParamField body="scenario" type="string">
  New scenario text.
</ParamField>

<ParamField body="expectedBehaviors" type="string[]">
  Replacement list of expected behaviors. Replaces the whole list, not a single entry.
</ParamField>

<ParamField body="personas" type="string[]">
  Replacement persona list, by name or identifier. An empty array is refused.
</ParamField>

<ParamField body="mockTools" type="object[]">
  Replacement list of mock tools. Same shape as on create; it replaces the whole
  list, not a single entry. Send `[]` to mock nothing.
</ParamField>

<ParamField body="env" type="object | null">
  Replacement env. Same shape as on create; it replaces the whole env, not a
  single key. Send `null` to clear it.
</ParamField>

<ParamField query="projectId" type="string">
  Project id or name. Defaults to the project your API key belongs to.
</ParamField>

### Response fields

Same shape as the create response: the full test object at its new (or unchanged) version.

### Conflict response

When the test has moved on, Egma returns `409 Conflict`:

```json
{
  "error": "version_conflict",
  "message": "this write was based on version tstv_old, and test tst_01abc has moved on to tstv_new",
  "test": { "id": "tst_01abc", "name": "reschedule appointment" },
  "expectedVersionId": "tstv_old",
  "currentVersionId": "tstv_new"
}
```

### Example

```bash
curl -X PATCH "https://your-egma-host/v1/tests/tst_01abc" \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "expectedVersionId": "tstv_01xyz",
    "expectedBehaviors": [
      "confirms the new time before ending the call",
      "does not ask for the same information twice",
      "offers a callback if no slots are available"
    ]
  }'
```

## Mock tool and env refusals

Both fields are checked at save, on create and on edit alike, so the CLI and the
web app get the same answer. Every refusal is `422 Unprocessable Entity` and
names what to change.

| Egma refuses | The message |
| --- | --- |
| The same tool named twice | `this test answers for "check_availability" twice; mock each tool once` |
| Both `answer` and `error` on one entry | `mock tool "check_availability" answers with one thing: this one sent both answer and error. Send whichever branch the test needs.` |
| Neither `answer` nor `error` | `mock tool "check_availability" answers with something: send answer with what the tool returns, or error with the failure it raises. This one sent neither.` |
| An answer over 15 KiB | `mock tool "check_availability": answer is 16104 bytes once serialized and tagged for the wire, and the exchange that carries it holds at most 15360. An answer that needs more than that is a document rather than a tool answer.` |
| A key `env` does not carry | `env has no "livekit_room_metadata" in it. An env carries retell_dynamic_variables and job_dispatch_metadata, and nothing else.` |
| A dynamic variable named `egma_…` | `env.retell_dynamic_variables names "egma_url_book", and Egma keeps every variable beginning "egma_" for the facts it writes into the conversation itself. Name the variable something else.` |
| A dynamic variable that is not text | `env.retell_dynamic_variables.caller_id is the text Retell substitutes into the prompt, and this request sent number.` |
| Dispatch metadata holding a lone surrogate | `env.job_dispatch_metadata holds a lone surrogate, which is valid JSON but has no UTF-8 form, so LiveKit could not carry it on the dispatch. Send well-formed text.` |
| Dispatch metadata over 512 KiB | `env.job_dispatch_metadata is 526336 bytes once serialized, and LiveKit carries at most 524288 on the dispatch; hold a large value in your own store and put its id here instead.` |

The two caps are the transports' own. A mock tool answer is measured as the
whole `{"answer": …}` exchange the lane sends, in UTF-8 bytes. Dispatch metadata
is measured on the exact compact JSON string Egma writes to the dispatch, so a
value that saves can never fail when the job starts.

## List tests

`GET /v1/tests`

Return a paginated list of active tests in one suite. Each item includes the
full test object with its current `versionId`.

### Query parameters

<ParamField query="projectId" type="string">
  Filter to a specific project by id or name.
</ParamField>

<ParamField query="suiteId" type="string" required>
  The `ste_…` suite ID whose tests to return.
</ParamField>

<ParamField query="pageToken" type="string">
  The `nextPageToken` value from the previous page. Omit to start from the newest test.
</ParamField>

### Response fields

<ResponseField name="tests" type="array">
  Array of test objects. Each has the same shape as the create response.
</ResponseField>

<ResponseField name="nextPageToken" type="string | null">
  Pass as `?pageToken` to fetch the next page. `null` means you are on the last page.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/v1/tests?projectId=my-project&suiteId=ste_01JXMK8P2QN4R6S9T1UV3WX5Y" \
  -H "Authorization: Bearer <api-key>"
```

## Delete a test

`DELETE /v1/tests/:testId`

Permanently remove one test from authoring and future runs. Its suite remains,
including when this was the suite's last test. There is no Restore action.
Completed simulation evidence keeps the exact test version it executed.

Send both `expectedVersionId` and `expectedRevision`. Egma compares them with
the Test's current content version and identity revision inside one deletion
transaction. If either one changed after you read the Test, Egma returns
`409 Conflict` and deletes nothing.

<ParamField path="testId" type="string" required>
  The `tst_…` identifier of the test to delete.
</ParamField>

<ParamField query="expectedVersionId" type="string" required>
  The `tstv_…` version identifier you last read.
</ParamField>

<ParamField query="expectedRevision" type="string" required>
  The `rev_…` identity revision you last read.
</ParamField>

## Get a test version

`GET /v1/test-versions/:versionId`

Retrieve a single frozen version by its `tstv_…` identifier. This is the shape a run pins and executes; it never changes after creation. The response also tells you whether this version is still the test's current one, and which test it belongs to.

### Path parameters

<ParamField path="versionId" type="string" required>
  The `tstv_…` version identifier.
</ParamField>

### Response fields

<ResponseField name="id" type="string">
  The version's own identifier (`tstv_…`).
</ResponseField>

<ResponseField name="testId" type="string">
  The test this version belongs to.
</ResponseField>

<ResponseField name="suiteId" type="string">
  The test's permanent suite ID.
</ResponseField>

<ResponseField name="testName" type="string">
  The test's current display name (names are not versioned).
</ResponseField>

<ResponseField name="version" type="integer">
  The version number within the test's history.
</ResponseField>

<ResponseField name="current" type="boolean">
  `true` if this is the test's current version. An older simulation may still
  name a prior exact version.
</ResponseField>

<ResponseField name="scenario" type="string">
  The frozen scenario text.
</ResponseField>

<ResponseField name="expectedBehaviors" type="string[]">
  The frozen list of expected behaviors.
</ResponseField>

<ResponseField name="personas" type="object[]">
  The frozen persona list. Same shape as on the test object.
</ResponseField>

<ResponseField name="mockTools" type="object[]">
  The frozen mock tools, in the shape the test object carries them.
</ResponseField>

<ResponseField name="env" type="object | null">
  The frozen env, or `null` where this version names none.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp of when this version was minted.
</ResponseField>

### Example

```bash
curl "https://your-egma-host/v1/test-versions/tstv_01xyz" \
  -H "Authorization: Bearer <api-key>"
```
