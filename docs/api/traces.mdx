Traces are the storage record of a conversation. Egma accepts standard
OTLP/HTTP from an agent process that already emits OpenTelemetry spans. LiveKit
Agents should use `monitor_livekit(ctx)` from the Egma Python SDK or
`monitorLiveKit(ctx)` from the Egma JavaScript SDK to create the required
telemetry setup. Retell Monitoring polls Retell and writes normalized
production traces without using this ingest endpoint. Use the read endpoints
below for either source.

---

## Ingest spans

Sends an OTLP export to Egma. Use this endpoint as the `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` (or equivalent) in your agent's OpenTelemetry configuration.

**`POST /v1/traces`**

### Authentication

Send a Bearer API key in the `Authorization` header. Customer OTLP production ingest requires a key scoped to the project that will own the telemetry. Egma rejects an organization-wide key before it decodes or stores the request body.

```
Authorization: Bearer egma_sk_...
```

### Content types

Send one of the two standard OTLP/HTTP content types:

| Format | `Content-Type` |
|---|---|
| Protobuf (recommended) | `application/x-protobuf` |
| JSON | `application/json` |

Gzip compression is supported. Add `Content-Encoding: gzip` when sending compressed bodies.

### Request limits

- Maximum body size: 20 MiB (matches the OpenTelemetry Collector default)
- Maximum spans per request: 10,000
- Maximum normalized row bytes per request: 64 MiB

Spans that exceed these limits are reported in the OTLP partial-success field — they will not be retried automatically. Split large exports into smaller batches.

### Response

Egma returns a standard `ExportTraceServiceResponse`. If any spans were rejected, the `partialSuccess` field contains a count and a reason. A `200` response with an empty body means all spans were accepted.

```bash title="Send spans (protobuf)"
curl -X POST https://your-egma-instance/v1/traces \
  -H "Authorization: Bearer egma_sk_..." \
  -H "Content-Type: application/x-protobuf" \
  --data-binary @export.pb
```

```bash title="Send spans (JSON)"
curl -X POST https://your-egma-instance/v1/traces \
  -H "Authorization: Bearer egma_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"resourceSpans": [...]}'
```

<Note>
  Prefer your Egma instance's API port for telemetry ingest — port **3100** by default. The web UI port (3101) also reaches this endpoint because the web application forwards `/v1/traces` to the API. The API is one hop shorter. Both addresses may differ in self-hosted deployments, so check `EGMA_URL`.
</Note>

<Note>
  In `OTEL_EXPORTER_OTLP_HEADERS`, encode the space in `Bearer egma_sk_...` as `%20`. A literal space can make an OpenTelemetry SDK reject or misread the header.
</Note>

<Warning>
  Customer OTLP production ingest requires a project-scoped API key. An organization-wide key is rejected, and Egma stores no spans from that request. Organization-wide keys can still use the trace read APIs to query across the organization. Mint an ingest key via `POST /v1/keys` with `projectId` set.
</Warning>

<Note>
  Egma removes credential fields and bearer-like values before it reads typed fields or stores the provider payload. Do not send secrets as telemetry attributes.
</Note>

## List traces

Returns a paginated list of trace summaries within a time window, ordered newest first.

**`GET /v1/traces`**

<ParamField query="from" type="string" required>
  Start of the query window as an RFC 3339 timestamp, e.g. `2026-08-02T00:00:00Z`. Microsecond precision is supported (six fractional digits); finer precision is rejected.
</ParamField>

<ParamField query="to" type="string" required>
  End of the query window as an RFC 3339 timestamp. The bound is exclusive — a trace that ended exactly at `to` is not included. You can paste a trace's own `endedAt` value directly as `to` without losing it.
</ParamField>

<ParamField query="projectId" type="string">
  Filter to a specific project. Omit to read across your whole organization. If your API key is already scoped to a project, this parameter must either match that project or be omitted.
</ParamField>

<ParamField query="source" type="string">
  Which kind of traffic to read: `simulation` for a conversation Egma conducted, `production` for one your own agent had. **Omit for both.** A value that is neither word is refused rather than ignored, and the refusal names both accepted words. Send the filter again with each page, alongside the same `from` and `to`.
</ParamField>

<ParamField query="pageSize" type="integer">
  Maximum traces per page. Clamped to the server maximum if higher. Must be a positive integer.
</ParamField>

<ParamField query="pageToken" type="string">
  Pagination cursor from a previous response's `nextPageToken`. Omit to start at the newest trace in the window.
</ParamField>

<ResponseField name="traces" type="array">
  Array of trace summary objects.
</ResponseField>

<ResponseField name="nextPageToken" type="string | null">
  Pass this as `pageToken` to fetch the next page. `null` means you have reached the last page.
</ResponseField>

<ResponseField name="window" type="object">
  The time window as Egma read it, formatted to microsecond precision. Use these values to paginate accurately.
</ResponseField>

```bash title="List traces in a time window"
curl "https://your-egma-instance/v1/traces?from=2026-08-01T00:00:00Z&to=2026-08-02T00:00:00Z" \
  -H "Authorization: Bearer egma_sk_..."
```

```bash title="Filter by project"
curl "https://your-egma-instance/v1/traces?from=2026-08-01T00:00:00Z&to=2026-08-02T00:00:00Z&projectId=prj_abc123" \
  -H "Authorization: Bearer egma_sk_..."
```

<Note>
  Both `from` and `to` are required. There is no default window — a query without a time bound would scan the entire store, and Egma rejects it with a descriptive error asking you to supply both parameters.
</Note>

### Trace summary fields

<ResponseField name="traceId" type="string">
  The 32-character lowercase hex trace ID.
</ResponseField>

<ResponseField name="startedAt" type="string">
  ISO 8601 timestamp of when the root span opened.
</ResponseField>

<ResponseField name="endedAt" type="string">
  ISO 8601 timestamp of when the root span closed.
</ResponseField>

<ResponseField name="durationNs" type="string">
  Total conversation duration in nanoseconds, as a decimal string. Sent as a string because nanosecond counts exceed the precision of a JSON number.
</ResponseField>

<ResponseField name="spanCount" type="number">
  Total number of spans in this trace.
</ResponseField>

<ResponseField name="turnCounts" type="object">
  `{ human, agent }` — number of turns attributed to each party.
</ResponseField>

<ResponseField name="source" type="string">
  `"simulation"` for runs Egma conducted, `"production"` for production evidence received through Monitoring or direct OTLP.
</ResponseField>

<ResponseField name="toolSpanCount" type="number">
  Number of tool-call spans in this trace.
</ResponseField>

<ResponseField name="erroredSpanCount" type="number">
  Number of spans that completed with an error status.
</ResponseField>

<ResponseField name="emitter" type="string">
  The SDK or agent process that emitted this trace.
</ResponseField>

<ResponseField name="environment" type="string">
  The deployment environment reported by the emitter, e.g. `"production"`.
</ResponseField>

<ResponseField name="connectionType" type="string">
  A connection type only when the emitter explicitly supplied one. Egma does not infer a production connection from an agent platform.
</ResponseField>

<ResponseField name="providerCallId" type="string">
  The provider-assigned call identifier, if the emitter included one.
</ResponseField>

<ResponseField name="agentPlatform" type="string">
  The agent platform that produced the production evidence, such as `retell` or `livekit`.
</ResponseField>

<ResponseField name="platformAgentId" type="string">
  The platform-owned agent identifier, when the platform supplied one.
</ResponseField>

<ResponseField name="platformAgentName" type="string">
  The platform-owned agent name observed for this conversation, when supplied.
</ResponseField>

<ResponseField name="platformAgentVersion" type="string">
  The platform-owned agent version observed for this conversation, when supplied.
</ResponseField>

<ResponseField name="runId" type="string">
  The run this trace belongs to, if it came from a simulation.
</ResponseField>

<ResponseField name="agentId" type="string">
  The agent identifier, if the emitter included one.
</ResponseField>

<ResponseField name="preview" type="string">
  A short excerpt from the conversation for display purposes.
</ResponseField>

## Get a trace

Returns the full transcript, metrics, and trace-level grades.

**`GET /v1/traces/:traceId`**

<ParamField path="traceId" type="string" required>
  The 32-character lowercase hex trace ID.
</ParamField>

<ParamField query="from" type="string" required>
  Start of the search window. Use the trace's own `startedAt` value, or a window that contains it.
</ParamField>

<ParamField query="to" type="string" required>
  End of the search window. Use the trace's own `endedAt` value, or a window that contains it.
</ParamField>

<ParamField query="projectId" type="string">
  Project filter. Follow the same rules as the list endpoint.
</ParamField>

<ResponseField name="trace" type="object">
  Full trace metadata. Same fields as the trace summary, without `preview`.
</ResponseField>

<ResponseField name="turns" type="array">
  Conversation turns in chronological order. Each turn has `spanId`, `name`, `kind`, `startedAt`, `durationNs`, `text`, and `audioUrl` (a pre-signed URL to the audio segment, if a recording is available).
</ResponseField>

<ResponseField name="spans" type="array">
  All spans in the trace, nested under their parents. Each span includes `spanId`, `parentSpanId`, `name`, `kind`, `status`, `startedAt`, `durationNs`, `text`, `audioUrl`, `toolName`, `toolArguments`, `toolResult`, and child `spans`.
</ResponseField>

<ResponseField name="spansTruncated" type="boolean">
  `true` when the trace exceeded the store's span limit and only the first spans are returned. Measures computed from a truncated trace are partial.
</ResponseField>

<ResponseField name="measures" type="array">
  Computed metrics for this conversation, such as turn response latency. Each entry has `measure`, `unit`, `samples`, `worst`, and `partial`.
</ResponseField>

<ResponseField name="simulationId" type="string | null">
  The Egma simulation ID for this trace, if it was conducted by Egma's simulator. `null` for production traces.
</ResponseField>

<ResponseField name="gradingState" type="string">
  Whole-trace grading progress: `not_requested`, `pending`, `running`,
  `complete`, or `error`.
</ResponseField>

<ResponseField name="grades" type="array">
  The current grade from each selected project grader. Each grade includes
  `projectGraderId`, `graderDefinitionId`, `graderDefinitionVersion`,
  `graderName`, a normalized `score` or `null`, `details`, the frozen
  `passThreshold`, its individual `result`, and `gradedAt`.
</ResponseField>

<ResponseField name="gradeHistory" type="array">
  Every appended grade for the trace. When a project grader runs more than
  once, its latest grade is current and older grades remain here.
</ResponseField>

<ResponseField name="combinedScore" type="number | null">
  The unweighted arithmetic mean of the current scores. It is `null` while
  selected grading is unfinished or when a selected grader errors.
</ResponseField>

An individual grade result can be `passed`, `failed`, or `errored`. It applies
only to that grader. Egma does not assign an overall `passed` or `failed` result
to the trace, test, test suite, or run, and it does not apply a threshold to
`combinedScore`.

```bash title="Get a trace"
curl "https://your-egma-instance/v1/traces/4bf92f3577b34da6a3ce929d0e0e4736?from=2026-08-01T00:00:00Z&to=2026-08-02T00:00:00Z" \
  -H "Authorization: Bearer egma_sk_..."
```

<Note>
  The `from` and `to` window is required for the detail endpoint too. The trace store is partitioned by time, and a lookup without a window must scan every partition. Pass the same window you used in the list query that found this trace — you already have those values in the list response.
</Note>
