This guide uses the CLI from your agent's repository. You need Node.js 22 or
newer, an Egma account with a project, and a working Retell or LiveKit agent.

If you prefer to work with a coding agent, install the [Skills](/tools/skills)
and ask it to set up simulation testing in your repository.

## 1. Install and sign in

```bash
npm install --global egma-cli
egma login
egma init
```

Approve the login in your browser. `egma init` binds the repository to your
project and pulls its current agents and test suites into `egma/`. If you do not
have a project yet, create one in Egma first. If the CLI needs a project ID,
use `egma init --project` with that project's ID.

For an existing `egma/config.yaml`, run `egma pull` before you make changes.
Review local edits before pulling.

<Note>
  For a self-hosted instance, first follow [Get started](/self-hosting/get-started).
  Use `egma login --url` with your instance URL, then `egma init --url` with the
  same URL. The rest of this guide is the same.
</Note>

## 2. Connect your agent

Follow the guide for your agent, then return here:

Keep the **Egma agent ID** and **connection ID** that the CLI prints. They are
also in `egma/config.yaml`. These are Egma IDs, not your provider's agent ID.
Set `EGMA_AGENT_ID` and `EGMA_CONNECTION_ID` in your shell to those values before
you run the commands below.

## 3. Create a suite and test

```bash
egma suite create smoke --name "Smoke"
egma persona list
```

The first command creates `egma/tests/smoke/suite.yaml` and the matching suite in
Egma. Keep this file; the CLI uses its ID when you sync and run the suite.

Create `egma/tests/smoke/repeat-request.md`:

````markdown
---
format: 5
name: Repeat a response
description: The caller asks the agent to repeat what it just said.
personas:
  - name: Everyday caller
---

## Scenario

Contact the agent and say hello. After its first response, say,
"Could you repeat that, please?" Listen to the repeated response, thank the
agent, and end the conversation. Do not request a booking, purchase, or other
change to an account.

## Expected behaviors

1. After the repeat request, the agent repeats the substance of its previous response.
2. The repeated response does not contradict the previous response.
3. The agent does not claim to have completed a booking, purchase, or account change.
````

`Everyday caller` is a built-in persona. Use the name returned by
`egma persona list` if you choose another persona. New tests do not need an ID
or version; Egma adds these when you sync.

This small test checks that a conversation can complete and produce useful
evidence. For your next test, use a task from your agent's prompt and write
expected behaviors that match its actual requirements.

If your agent needs startup data, add the [Retell dynamic variables](/guides/retell#pass-data-to-a-test)
or [LiveKit dispatch metadata](/guides/livekit#pass-data-to-a-test) it normally
receives. Put realistic, non-secret test values in the file.

<Warning>
  Tools without a mock run their real implementation. If your agent can write
  data during this conversation, add [mock tool responses](/guides/mock-tool-responses)
  for those tools before you run the test.
</Warning>

## 4. Start the run

```bash
egma run create smoke \
  --agent "$EGMA_AGENT_ID" \
  --connection "$EGMA_CONNECTION_ID" \
  --name "First smoke test"
```

`smoke` is the directory under `egma/tests/`. The command pushes your local
project changes first. If the push fails, Egma does not start a run.

On success, the CLI prints a run ID and a results URL. Open that URL. The
command returns after starting the run; it does not wait for simulations or
grading to finish.

## 5. Read the result

Wait for the simulation and its grading to finish, then open the simulation:

1. Read the transcript. Find the repeat request and the agent's next response.
2. Open the **Expected behaviors** grade. Check the result for each behavior
   against the transcript.
3. Inspect any tool calls. Confirm that the test exercised the path you meant
   to test. For voice simulations, listen to the recording when it is available.

A low grade means the observed behavior missed the grader's threshold. An
execution or grading error means that step did not finish; read the error
before drawing a conclusion about your agent.

## 6. Change one thing and run again

Change the scenario to ask for a repeat twice, or replace it with a common task
your agent handles. Update the expected behaviors to match that situation.
If the agent failed a valid requirement, change the agent instead.

Start another run with the same command and compare the two conversations.
Commit the files in `egma/` with the agent changes they test. Keep credentials
in your environment or secret store.

Continue with [Write a test](/guides/write-a-test) or
[Set up monitoring](/guides/set-up-monitoring).
