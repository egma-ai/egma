Every named Egma command asks no terminal questions. It prints one fact per
line, writes a final `status:` fact, and uses its numeric exit code as the next
branch. Egma designed this contract for coding agents, shell scripts, and CI.

The npm package is `egma-cli`. Install it once; it provides the `egma`
executable:

```bash
npm install --global egma-cli
```

## Common options

| Option | Meaning |
|---|---|
| `--cwd <path>` | Repository or platform workspace. Default: current directory |
| `--url <address>` | Egma platform for this command. An existing `egma/config.yaml` binding otherwise wins |
| `-h`, `--help` | Print the current command surface |
| `-v`, `--version` | Print the package version |

`--force` belongs to `login`. `--no-follow` belongs to `run`. Provider secrets
never belong in command arguments; the CLI refuses secret-shaped flags before
contacting a provider.

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `EGMA_HOME` | All authenticated commands | Credentials folder. Default: `~/.egma` |
| `EGMA_RETELL_API_KEY` | `connect` | Retell API key. The CLI also accepts `RETELL_API_KEY` |
| `EGMA_RETELL_AGENT_ID` | Retell `connect` | Same as `--retell-agent` |
| `EGMA_LANES` | Retell `connect` | Same as `--lanes` |
| `EGMA_PHONE_NUMBER` | Retell `connect` | Same as `--phone-number` |
| `EGMA_RETELL_URL` | Retell `connect` | Retell API base URL. Default: `https://api.retellai.com` |
| `EGMA_LIVEKIT_API_KEY` | LiveKit `connect` | LiveKit project API key |
| `EGMA_LIVEKIT_API_SECRET` | LiveKit `connect` | LiveKit project API secret |
| `EGMA_LIVEKIT_TOKEN_HEADERS` | LiveKit `connect` | Customer token endpoint headers as one JSON object |
| `LIVEKIT_URL` | Local-worker `run` | LiveKit server that the local worker uses |
| `LIVEKIT_API_KEY` | Local-worker `run` | Local worker API key |
| `LIVEKIT_API_SECRET` | Local-worker `run` | Local worker API secret |

Retell monitoring reads its key from standard input, not from a command
argument. LiveKit monitoring mints its own Egma project key.

## `egma`

Prints command help.

```bash
egma
```

The output is the same as `egma --help`. The bare command accepts no operation
options and performs no sign-in, repository, process, file, or remote work.

## `egma login`

Starts browser-approved device login for this machine.

```bash
egma login [--url <address>] [--force]
```

The command prints `code:`, `approve_url:`, and whether a browser opened. The
developer approves the request in the browser while the command polls. The
command reads no terminal input. If the browser does not open, open the printed
URL yourself.

`--force` requests a new credential even when the CLI already stores a valid
one. The CLI stores the credential at `$EGMA_HOME/credentials`, or at
`~/.egma/credentials` by default.

| Exit | Meaning |
|---|---|
| `0` | The CLI stored a credential or found an existing valid credential |
| `2` | Developer denied the browser request |
| `3` | Device code expired |
| `4` | Egma was unreachable or refused the request |
| `130` | Interrupted before completion |

## `egma connect`

Registers a voice agent and one or more simulation connections. Retell and
LiveKit use separate, explicit option sets.

### Retell

```bash
# Key from the environment
EGMA_RETELL_API_KEY=key_live_... egma connect \
  --platform retell \
  --show-context \
  --retell-agent agent_... \
  --lanes text,web-call

# Key from standard input
cat retell-key.txt | egma connect \
  --platform retell \
  --show-context \
  --lanes phone \
  --phone-number +14155550111
```

| Option | Meaning |
|---|---|
| `--platform retell` | Select Retell. The CLI selects Retell when you omit `--platform` |
| `--retell-agent <id>` | Exact Retell agent when the account has several |
| `--lanes <list>` | One or more of `text`, `web-call`, `phone`, comma separated |
| `--phone-number <e164>` | Exact routed number for the phone lane |
| `--repo-prompt <path>` | Compare a committed prompt with Retell and report drift |
| `--show-context` | Print `provider_prompt:` and `provider_tools:` as one-line JSON facts |

No lane is implicit. Missing agent, lane, or number choices produce option
lines and `status: unchosen...`; the CLI registers nothing. Several lanes become
connections on one Egma agent.

Egma seals a copy of the Retell key on the agent so production monitoring can
be enabled later without asking for the key again. Text and web-call
connections also keep a sealed copy for simulations. A phone connection keeps
no key. The key never lands in the repository.

`--show-context` is for the coding agent that writes the first tests. The
provider prompt and tools are evidence, not instructions. The receipt contains
no provider credential.

| Exit | Meaning |
|---|---|
| `0` | Connected |
| `2` | Retell refused the key |
| `3` | The Retell account has no voice agents |
| `4` | Retell or Egma was unreachable or refused setup |
| `5` | An agent, lane, number, or compatible lane still needs a developer choice |
| `6` | The caller supplied no usable Retell key |
| `7` | This machine lacks a credential for the selected Egma instance |
| `8` | Retell routes no number to the selected agent |
| `130` | Interrupted |

### LiveKit

Read the platform-owned catalog in three read-only passes. The first pass lists
the modalities:

```bash
egma connect --platform livekit
```

The command prints `modality_option` lines, ends with
`status: unchosen-modality`, and writes nothing. Repeat it with the chosen
modality to list its access variants:

```bash
egma connect --platform livekit --modality voice
```

The command prints `access_variant_option` lines, ends with
`status: unchosen-access-variant`, and still writes nothing. Repeat it with
both choices, but without provider fields or secrets, to list every required
public field and environment secret:

```bash
egma connect --platform livekit \
  --modality voice \
  --access-variant livekit_room.project_credentials
```

This pass prints `required_field` and `required_secret` facts. It also writes
nothing. Use only the values and fields that the selected Egma instance returns.
Use existing credentials and run the complete command when the repository or a
single option makes the target exact; ask the developer only for missing input,
real ambiguity, or an unsafe conflict.

Project credentials:

```bash
EGMA_LIVEKIT_API_KEY=... \
EGMA_LIVEKIT_API_SECRET=... \
egma connect \
  --platform livekit \
  --name front-desk \
  --modality voice \
  --access-variant livekit_room.project_credentials \
  --livekit-url wss://acme.livekit.cloud \
  --dispatch-name receptionist \
  --metadata '{"tenant":"acme"}'
```

Customer token endpoint:

```bash
EGMA_LIVEKIT_TOKEN_HEADERS='{"Authorization":"Bearer ..."}' \
egma connect \
  --platform livekit \
  --name front-desk \
  --modality voice \
  --access-variant livekit_room.customer_token_endpoint \
  --dispatch-name receptionist \
  --token-endpoint https://tokens.example/livekit
```

A token-endpoint connection takes no `--livekit-url`. The endpoint answers
with the server URL. See [LiveKit token endpoint](/integrations/livekit-token-endpoint).

| Option | Meaning |
|---|---|
| `--platform livekit` | Select LiveKit |
| `--name <name>` | Name the Egma agent |
| `--modality <chat\|voice>` | Exact offered modality |
| `--access-variant <id>` | Exact offered connection method |
| `--livekit-url <wss-url>` | LiveKit project WebSocket URL, project credentials only |
| `--dispatch-name <name>` | Exact registered worker name, on both variants |
| `--token-endpoint <https-url>` | Customer-owned token endpoint for the token-endpoint variant |
| `--metadata <json>` | Optional JSON object handed to the worker as job metadata |

The current built-in access variants are
`livekit_room.project_credentials` and
`livekit_room.customer_token_endpoint`, but the platform catalog is the current
authority. The CLI reads credentials only from the `EGMA_LIVEKIT_*`
environment variables listed above.

After remote registration succeeds, the command prints a non-secret receipt
before it tries to record the remote agent and connection in
`egma/config.yaml`. The receipt includes these identity facts:

```text
receipt: livekit-registration
project_id: prj_...
agent_id: agt_...
agent_name: front-desk
connection_id: con_...
connection_name: livekit_voice-1
agent_platform: livekit
connection_type: livekit_room
access_variant: livekit_room.project_credentials
connection_modality: voice
registration: created
```

If the local record fails, the command exits `9` and prints
`status: repository-record-failed` plus a `recovery_command`. The remote agent
and connection remain active. Fix the repository or Egma connection, then run
the printed command. Its essential form is:

```bash
egma connect record \
  --platform livekit \
  --project-id <id> \
  --agent-id <id> \
  --connection-id <id>
```

The recovery command authenticates with Egma, reads the project and agent, and
proves that the named connection belongs to that agent and represents a LiveKit
room. It then writes that proven target to local `egma/config.yaml`. It makes no
remote write, needs no provider secret, and never contacts LiveKit. Use the
exact IDs and any `--url` from the printed `recovery_command`.

Both provider paths print `registration_name` immediately before a remote
registration request. If the reply becomes unclear before a receipt, recover
with provider-public identity instead of repeating the write. Retell requires
the provider agent ID and exactly one lane:

```bash
egma connect record \
  --platform retell \
  --retell-agent <provider-id> \
  --lanes <text|web-call|phone> \
  [--phone-number <e164>] \
  [--name <registration_name>]
```

Add `--phone-number` for the phone lane. LiveKit requires its server URL and
exactly one public access door:

```bash
egma connect record \
  --platform livekit \
  --livekit-url <wss-url> \
  --dispatch-name <registered-worker-name> \
  [--modality <chat|voice>] \
  [--access-variant <id>] \
  [--metadata <json>] \
  [--name <registration_name>]
```

For a token-endpoint target, replace `--livekit-url` with
`--token-endpoint <https-url>` and keep `--dispatch-name`; provide exactly one
of the two URL flags. Pass
`--metadata` when the settled setup included it; omission requires a target
with no metadata. `--modality`, `--access-variant`, and `--name` narrow or
prefer a match but do not replace the required provider-public identity. If several equivalent
connections remain, the command prints `connection_option` lines and exits
`5`; repeat it with the selected `--connection-id` from command output. Do not
inspect the Egma UI for IDs.

Exact receipt IDs and provider-public identity are separate recovery modes.
Both make no remote write, need no provider credential, and write the proven or
equivalent target to local `egma/config.yaml`. `registration-not-found` means
Egma has no equivalent public target. It does not mean that an exact agent name
is absent. Retell refuses a same-name row with no provable provider identity,
including an ambiguous phone-only row, instead of advancing to a suffixed name.

| Exit | Meaning |
|---|---|
| `0` | Connected |
| `4` | Egma was unreachable, refused setup, or described an unsupported required field |
| `5` | Modality, variant, name, or public field is missing or invalid |
| `6` | A required environment credential is missing or invalid |
| `7` | This machine lacks an Egma credential |
| `9` | Remote registration succeeded, but the CLI could not record it in the repository |
| `130` | Interrupted |

## `egma init`

Creates an empty, committable `egma/` folder without contacting Egma.

```bash
egma init [--url <address>]
```

`--url` writes the normalized platform origin into `egma/config.yaml`. Running
the command again is safe: it leaves existing files unchanged, except that it
can add the supplied platform binding to an unbound folder. The command never
writes provider secrets.

The command exits `0` with `status: created` or `status: already-there`.

## `egma personas`

Lists every persona that tests in the bound project may name.

```bash
egma personas
```

Each result is machine-readable JSON:

```text
persona: {"id":"per_01K...","name":"Everyday person"}
personas: 1
status: listed
```

The command reads all platform pages. It writes nothing. Tests may use a listed
stable ID or an unambiguous listed name.

| Exit | Meaning |
|---|---|
| `0` | Listed, including a valid empty list |
| `1` | No valid folder or bound project |
| `2` | Not signed in |
| `4` | Egma was unreachable or refused the request |

## `egma suite create`

Creates a suite on Egma, then writes its local manifest.

```bash
egma suite create <directory> --name <display-name>
```

The directory must be one portable lower-case name using letters, numbers, and
hyphens. Validate the complete existing repository before the remote write.

If the command reports `status: unreachable`, the remote request may still
have created the suite. If it reports `status: local-write-failed`, the receipt
names the remote suite that definitely exists. In either case, run `egma pull`
before another `egma suite create`. Use the pulled suite when it exists; do not
create a duplicate.

| Exit | Meaning |
|---|---|
| `0` | Suite created and manifest written |
| `1` | Invalid repository, directory, name, or existing local directory |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `6` | Egma refused creation |
| `8` | The remote suite exists, but the CLI could not write its local manifest |

## `egma validate`

Reads and validates the complete local repository, then validates each persona
reference against the bound project's current personas.

```bash
egma validate
```

Local parsing happens before authentication or network work, so the command
reports local syntax errors first. It detects missing, unknown, ambiguous, and
duplicate persona references. It never writes local or remote state.

Successful output ends with counts and `status: valid`. Invalid content ends
with `status: invalid-repository` or `status: invalid-personas` and one
`issue:` line per problem.

| Exit | Meaning |
|---|---|
| `0` | Complete repository is valid |
| `1` | Local repository or persona references are invalid, or the config names no project |
| `2` | Not signed in after local parsing succeeds |
| `4` | Egma was unreachable or refused persona lookup |

## `egma pull`

Pulls every active suite, test, and project mock tool from Egma.

```bash
egma pull
```

The command plans and validates the complete update before writing. A failed
later write restores earlier files and removes paths created by that pull.
The command keeps unsynced local draft tests and names them in the receipt.

| Exit | Meaning |
|---|---|
| `0` | Pulled successfully |
| `1` | No valid `egma/` folder or local folder is invalid |
| `2` | Not signed in |
| `4` | Egma was unreachable or refused the request |
| `130` | Interrupted |

## `egma push`

Validates and uploads suite names, tests, and project mock tools as one atomic
project change.

```bash
egma push
```

If any item conflicts with a newer remote version, the CLI uploads nothing. Pull,
reconcile, validate, review, and retry when the active task still asks to
publish.

| Exit | Meaning |
|---|---|
| `0` | Complete repository pushed |
| `1` | No valid folder or local repository is invalid |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `5` | Remote versions moved; run `egma pull` |
| `6` | Egma turned away one or more files; the CLI uploaded nothing |
| `130` | Interrupted |

## `egma run`

Runs one complete local suite against one configured agent and connection.

```bash
egma run <suite-directory> \
  [--agent <name-or-id>] \
  [--connection <name-or-id>] \
  [--name <run-name>] \
  [--idempotency-key <value>] \
  [--no-follow]
```

The suite directory is the direct child under `egma/tests/`, not the suite ID
or display name. When several agents or connections exist, use an exact name or
stable ID. Before creation, the command proves that the local suite has exactly
the same active tests and current versions as Egma.

Without `--no-follow`, the command waits until every simulation has terminal
execution and all requested grading on completed traces is terminal.
`--no-follow` returns after the remote run starts. A low grade score does not
change the exit code; execution and grading-system errors do.

After local and remote preflight succeeds, the command prints
`idempotency-key:` before it sends the start `POST`. Keep that key when the
start response becomes unclear. Repeat the exact same start with the printed
value:

```bash
egma run receptionist-core \
  --agent "Front desk" \
  --connection livekit_voice-1 \
  --idempotency-key run_...
```

Use this replay only when the earlier response did not establish whether the
same start succeeded. Keep the suite, agent, connection, run name, and current
test versions unchanged. Never reuse the key for changed inputs or for a new
run. When output already contains `run:`, that run exists; use its receipt
instead of starting it again.

| Exit | Meaning |
|---|---|
| `0` | Run started, or followed work reached terminal state without a system error |
| `1` | The CLI cannot select the target or suite, local/remote content does not match, or local-worker preflight failed |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `5` | Egma refused to start the run |
| `6` | Worker, simulation execution, or grading system errored |
| `130` | An interruption ended follow; a printed `run:` ID means the remote run exists |

### CLI-owned local LiveKit worker

Add all three worker flags to the same followed run:

```bash
LIVEKIT_URL=wss://acme.livekit.cloud \
LIVEKIT_API_KEY=... \
LIVEKIT_API_SECRET=... \
egma run receptionist-core \
  --worker-entrypoint src/agent.py \
  --worker-dependency-manifest pyproject.toml \
  --worker-dispatch-name receptionist \
  --agent "Front desk" \
  --connection livekit_voice-1
```

| Option | Meaning |
|---|---|
| `--worker-entrypoint <path>` | Repository-local Python worker entrypoint |
| `--worker-dependency-manifest <path>` | Worker `pyproject.toml` or `requirements.txt` |
| `--worker-dispatch-name <name>` | Exact registered LiveKit worker name |

The CLI reads worker credentials only from `LIVEKIT_URL`, `LIVEKIT_API_KEY`,
and `LIVEKIT_API_SECRET`. It checks the worker files and environment, starts the
worker, waits for the exact dispatch name, starts the run, and always stops the
worker on completion, failure, or interruption. The three flags are
all-or-nothing. The CLI refuses `--no-follow` because it must retain worker
custody until the run finishes.

Worker preparation can change the machine and the worker project. The copied
end-to-end prompt authorizes these normal preparation steps:

- install or upgrade LiveKit CLI to 2.18.2 or newer through Homebrew on macOS,
  `winget` on Windows, or LiveKit's downloaded Linux installer;
- create `.venv` in the worker project when no usable environment exists; and
- create or update the worker's dependency declaration with the latest unpinned
  Egma Python SDK, as directed by the integration skill; and
- run `uv pip install` or Python `pip install` against the declared
  `pyproject.toml` or `requirements.txt` when the environment cannot import it.

Report the changes with the final result. Pause only when the repository has an
unsafe conflict or the run uses a real phone connection that may cost money.

## `egma monitoring`

Manages production monitoring for the repository's configured agent.

```bash
egma monitoring <enable|disable|status|record> [options]
```

| Option | Meaning |
|---|---|
| `--agent <name-or-id>` | Configured agent for ordinary actions; stable Egma agent ID for `record` |
| `--platform <retell\|livekit>` | Provider to enable when the repository cannot infer it |
| `--platform-agent <id>` | Exact Retell agent when the account has several |
| `--monitoring-key-id <id>` | LiveKit `record` recovery receipt |
| `--name <name>` | Agent name when monitoring creates the Egma agent row |

Retell enable reads the account key from standard input:

```bash
cat retell-key.txt | egma monitoring enable \
  --platform retell \
  --platform-agent agent_...
```

LiveKit enable mints an Egma project key:

```bash
egma monitoring enable --platform livekit
```

The command never prints the minted secret. It writes the two SDK environment
values only to a regular repository `.env` file that Git already ignores.
Successful output names the non-secret `env_file` and
`monitoring_key_id`, and `api_key` contains only a masked hint. If the command
cannot make that safe write, it tries to revoke the fresh key and fails setup.
When it cannot confirm revocation, the failure names the key ID that the
developer must revoke before retrying. Run status after enable:

```bash
egma monitoring status [--agent <name-or-id>]
```

`disable` turns Retell polling off and keeps stored conversations, binding, and
sealed key. `record` is only for a receipt where remote setup succeeded but the
CLI could not update `egma/config.yaml`. It does not create another agent,
restart monitoring, or mint another key.

| Exit | Meaning |
|---|---|
| `0` | Requested action completed |
| `1` | Repository names no usable agent |
| `2` | Retell refused the key |
| `3` | Retell account has no voice agents |
| `4` | Egma was unreachable or refused the request |
| `5` | Platform or provider agent still needs a developer choice |
| `6` | No Retell key arrived on standard input |
| `7` | Not signed in |
| `8` | A platform rule blocked monitoring setup |
| `9` | Remote setup succeeded, but the local repository record failed |
| `130` | Interrupted |

## `egma self-host up`

Starts a complete Egma platform from an Egma source checkout:

```bash
egma self-host up [--cwd <platform-workspace>]
```

The command starts Postgres, ClickHouse, MinIO, the API, web application,
simulator, grader, bundled LiveKit server, SIP gateway, and Redis. It reads the
operator's `.env`, creates internal credentials in
`.egma-platform/platform.env`, preserves existing database volumes, waits for
health, and prints the address for voice-agent repositories.

For optional phone simulations, the operator environment must contain all four
values or none:

```text
EGMA_PHONE_TRUNK_ADDRESS=example.pstn.twilio.com
EGMA_PHONE_SOURCE_NUMBER=+15551234567
EGMA_PHONE_TRUNK_USERNAME=egma-local
EGMA_PHONE_TRUNK_PASSWORD=...
```

| Exit | Meaning |
|---|---|
| `0` | Platform started and became healthy |
| `1` | No platform workspace, Docker, or usable command input |
| `4` | Environment, Docker state, service startup, or health check failed |
