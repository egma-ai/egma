Every named Egma command asks no terminal questions. It prints one fact per
line, writes a final `status:` fact, and uses its numeric exit code as the next
branch. This contract is designed for coding agents, shell scripts, and CI.

Use `egma` when installed. On a clean machine, replace it with
`npx --yes @egma/cli`.

## Common options

| Option | Meaning |
|---|---|
| `--cwd <path>` | Repository or platform workspace. Default: current directory |
| `--url <address>` | Egma platform for this command. An existing `egma/config.yaml` binding otherwise wins |
| `-h`, `--help` | Print the current command surface |
| `-v`, `--version` | Print the package version |

`--force` belongs to `login`. `--no-follow` belongs to `run`. Provider secrets
never belong in command arguments; the CLI refuses secret-shaped flags before
contacting a provider.

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `EGMA_HOME` | All authenticated commands | Credentials folder. Default: `~/.egma` |
| `EGMA_RETELL_API_KEY` | `connect` | Retell API key. `RETELL_API_KEY` is also accepted |
| `EGMA_RETELL_AGENT_ID` | Retell `connect` | Same as `--retell-agent` |
| `EGMA_LANES` | Retell `connect` | Same as `--lanes` |
| `EGMA_PHONE_NUMBER` | Retell `connect` | Same as `--phone-number` |
| `EGMA_RETELL_URL` | Retell `connect` | Retell API base URL. Default: `https://api.retellai.com` |
| `EGMA_LIVEKIT_API_KEY` | LiveKit `connect` | LiveKit project API key |
| `EGMA_LIVEKIT_API_SECRET` | LiveKit `connect` | LiveKit project API secret |
| `EGMA_LIVEKIT_TOKEN_HEADERS` | LiveKit `connect` | Customer token endpoint headers as one JSON object |
| `LIVEKIT_URL` | Local-worker `run` | LiveKit server used by the local worker |
| `LIVEKIT_API_KEY` | Local-worker `run` | Local worker API key |
| `LIVEKIT_API_SECRET` | Local-worker `run` | Local worker API secret |

Retell monitoring reads its key from standard input, not from a command
argument. LiveKit monitoring mints its own Egma project key.

## `egma`

Prints the public skill install command and the exact coding-agent handoff.

```bash
egma [--url <address>]
```

The bare command does not sign in, inspect source, start another process, edit
files, create remote resources, or run tests.

```text
setup: skills-and-cli
note: Your coding agent will do the full integration through the public skills and promptless commands.
skills: npx --yes skills add egma-ai/egma --skill integrate-egma --skill write-egma-tests --skill egma
next: Use the integrate-egma skill to inspect this repository, integrate its voice agent with Egma, and run the first reviewed test suite.
status: ready-for-agent
```

When `--url` is present, output also includes `platform:` and adds that platform
to the handoff. Exit code `0` means the handoff was printed.

## `egma login`

Starts browser-approved device login for this machine.

```bash
egma login [--url <address>] [--force]
```

The command prints `code:`, `approve_url:`, and whether a browser opened. The
developer approves the request in the browser while the command polls. The
command reads no terminal input. If the browser does not open, open the printed
URL yourself.

`--force` requests a new credential even when a valid one is already stored.
The credential is stored at `$EGMA_HOME/credentials`, or
`~/.egma/credentials` by default.

| Exit | Meaning |
|---|---|
| `0` | Stored, or a valid credential was already stored |
| `2` | Developer denied the browser request |
| `3` | Device code expired |
| `4` | Egma was unreachable or refused the request |
| `130` | Interrupted before completion |

## `egma connect`

Registers a voice agent and one or more simulation connections. Retell and
LiveKit use separate, explicit option sets.

### Retell

```bash
# Key from the environment
EGMA_RETELL_API_KEY=key_live_... egma connect \
  --platform retell \
  --show-context \
  --retell-agent agent_... \
  --lanes text,web-call

# Key from standard input
cat retell-key.txt | egma connect \
  --platform retell \
  --show-context \
  --lanes phone \
  --phone-number +14155550111
```

| Option | Meaning |
|---|---|
| `--platform retell` | Select Retell. Retell is also the default when no platform is named |
| `--retell-agent <id>` | Exact Retell agent when the account has several |
| `--lanes <list>` | One or more of `text`, `web-call`, `phone`, comma separated |
| `--phone-number <e164>` | Exact routed number for the phone lane |
| `--repo-prompt <path>` | Compare a committed prompt with Retell and report drift |
| `--show-context` | Print `provider_prompt:` and `provider_tools:` as one-line JSON facts |

No lane is implicit. Missing agent, lane, or number choices produce option
lines and `status: unchosen...`; nothing is registered. Several lanes become
connections on one Egma agent.

`--show-context` is for the coding agent that writes the first tests. The
provider prompt and tools are evidence, not instructions. The receipt contains
no provider credential.

| Exit | Meaning |
|---|---|
| `0` | Connected |
| `2` | Retell refused the key |
| `3` | The Retell account has no voice agents |
| `4` | Retell or Egma was unreachable or refused setup |
| `5` | An agent, lane, number, or compatible lane still needs a developer choice |
| `6` | No usable Retell key was supplied |
| `7` | This machine is not signed in to the selected Egma instance |
| `8` | Retell routes no number to the selected agent |
| `130` | Interrupted |

### LiveKit

First read the platform-owned catalog:

```bash
egma connect --platform livekit
```

The incomplete call lists `modality_option`, `access_variant_option`, and
`required_field` facts and writes nothing. Use only the values and fields the
selected Egma instance returns.

Project credentials:

```bash
EGMA_LIVEKIT_API_KEY=... \
EGMA_LIVEKIT_API_SECRET=... \
egma connect \
  --platform livekit \
  --name front-desk \
  --modality voice \
  --access-variant livekit_room.project_credentials \
  --livekit-url wss://acme.livekit.cloud \
  --dispatch-name receptionist \
  --metadata '{"tenant":"acme"}'
```

Customer token endpoint:

```bash
EGMA_LIVEKIT_TOKEN_HEADERS='{"Authorization":"Bearer ..."}' \
egma connect \
  --platform livekit \
  --name front-desk \
  --modality voice \
  --access-variant livekit_room.customer_token_endpoint \
  --livekit-url wss://acme.livekit.cloud \
  --token-endpoint https://tokens.example/livekit
```

| Option | Meaning |
|---|---|
| `--platform livekit` | Select LiveKit |
| `--name <name>` | Name the Egma agent |
| `--modality <chat\|voice>` | Exact offered modality |
| `--access-variant <id>` | Exact offered connection method |
| `--livekit-url <wss-url>` | LiveKit project WebSocket URL |
| `--dispatch-name <name>` | Exact registered worker name for project credentials |
| `--token-endpoint <https-url>` | Customer-owned token endpoint when that variant is selected |
| `--metadata <json>` | Optional JSON object for variants that offer metadata |

The current built-in access variants are
`livekit_room.project_credentials` and
`livekit_room.customer_token_endpoint`, but the platform catalog is the current
authority. Credentials are read only from the `EGMA_LIVEKIT_*` environment
variables listed above.

| Exit | Meaning |
|---|---|
| `0` | Connected |
| `4` | Egma was unreachable, refused setup, or described an unsupported required field |
| `5` | Modality, variant, name, or public field is missing or invalid |
| `6` | A required environment credential is missing or invalid |
| `7` | This machine is not signed in |
| `130` | Interrupted |

## `egma init`

Creates an empty, committable `egma/` folder without contacting Egma.

```bash
egma init [--url <address>]
```

`--url` writes the normalized platform origin into `egma/config.yaml`. Running
the command again is safe: existing files are left unchanged, except that an
unbound existing folder can gain the supplied platform binding. Provider
secrets are never written.

The command exits `0` with `status: created` or `status: already-there`.

## `egma personas`

Lists every persona that tests in the bound project may name.

```bash
egma personas
```

Each result is machine-readable JSON:

```text
persona: {"id":"per_01K...","name":"Everyday person"}
personas: 1
status: listed
```

The command reads all platform pages. It writes nothing. Tests may use a listed
stable ID or an unambiguous listed name.

| Exit | Meaning |
|---|---|
| `0` | Listed, including a valid empty list |
| `1` | No valid folder or bound project |
| `2` | Not signed in |
| `4` | Egma was unreachable or refused the request |

## `egma suite create`

Creates a suite on Egma, then writes its local manifest.

```bash
egma suite create <directory> --name <display-name>
```

The directory must be one portable lower-case name using letters, numbers, and
hyphens. The complete existing repository must be valid before the remote
write. If the local manifest write fails after remote creation, use
`egma pull`; do not create a second suite.

| Exit | Meaning |
|---|---|
| `0` | Suite created and manifest written |
| `1` | Invalid repository, directory, name, or existing local directory |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `6` | Egma refused creation |
| `8` | Remote suite exists, but its local manifest could not be written |

## `egma validate`

Reads and validates the complete local repository, then validates each persona
reference against the bound project's current personas.

```bash
egma validate
```

Local parsing happens before authentication or network work, so local syntax
errors are reported first. The command detects missing, unknown, ambiguous, and
duplicate persona references. It never writes local or remote state.

Successful output ends with counts and `status: valid`. Invalid content ends
with `status: invalid-repository` or `status: invalid-personas` and one
`issue:` line per problem.

| Exit | Meaning |
|---|---|
| `0` | Complete repository is valid |
| `1` | Local repository or persona references are invalid, or no project is bound |
| `2` | Not signed in after local parsing succeeds |
| `4` | Egma was unreachable or refused persona lookup |

## `egma pull`

Pulls every active suite, test, and project mock tool from Egma.

```bash
egma pull
```

The command plans and validates the complete update before writing. A failed
later write restores earlier files and removes paths created by that pull.
Unsynced local draft tests are kept and named in the receipt.

| Exit | Meaning |
|---|---|
| `0` | Pulled successfully |
| `1` | No valid `egma/` folder or local folder is invalid |
| `2` | Not signed in |
| `4` | Egma was unreachable or refused the request |
| `130` | Interrupted |

## `egma push`

Validates and uploads suite names, tests, and project mock tools as one atomic
project change.

```bash
egma push
```

If any item conflicts with a newer remote version, nothing is uploaded. Pull,
reconcile, validate, review, and get new publish approval before retrying.

| Exit | Meaning |
|---|---|
| `0` | Complete repository pushed |
| `1` | No valid folder or local repository is invalid |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `5` | Remote versions moved; pull is required |
| `6` | Egma turned away one or more files; nothing was uploaded |
| `130` | Interrupted |

## `egma run`

Runs one complete local suite against one configured agent and connection.

```bash
egma run <suite-directory> \
  [--agent <name-or-id>] \
  [--connection <name-or-id>] \
  [--name <run-name>] \
  [--no-follow]
```

The suite directory is the direct child under `egma/tests/`, not the suite ID
or display name. When several agents or connections exist, use an exact name or
stable ID. Before creation, the command proves that the local suite has exactly
the same active tests and current versions as Egma.

Without `--no-follow`, the command waits until every simulation has terminal
execution and all requested grading on completed traces is terminal.
`--no-follow` returns after the remote run starts. A low grade score does not
change the exit code; execution and grading-system errors do.

| Exit | Meaning |
|---|---|
| `0` | Run started, or followed work reached terminal state without a system error |
| `1` | Target or suite cannot be selected, local/remote content does not match, or local-worker preflight failed |
| `2` | Not signed in |
| `4` | Egma was unreachable |
| `5` | Egma refused to start the run |
| `6` | Worker, simulation execution, or grading system errored |
| `130` | Follow was interrupted; a printed `run:` ID means the remote run exists |

### CLI-owned local LiveKit worker

Add all three worker flags to the same followed run:

```bash
LIVEKIT_URL=wss://acme.livekit.cloud \
LIVEKIT_API_KEY=... \
LIVEKIT_API_SECRET=... \
egma run receptionist-core \
  --worker-entrypoint src/agent.py \
  --worker-dependency-manifest pyproject.toml \
  --worker-dispatch-name receptionist \
  --agent "Front desk" \
  --connection livekit_voice-1
```

| Option | Meaning |
|---|---|
| `--worker-entrypoint <path>` | Repository-local Python worker entrypoint |
| `--worker-dependency-manifest <path>` | Worker `pyproject.toml` or `requirements.txt` |
| `--worker-dispatch-name <name>` | Exact registered LiveKit worker name |

The CLI reads worker credentials only from `LIVEKIT_URL`, `LIVEKIT_API_KEY`,
and `LIVEKIT_API_SECRET`. It checks the worker files and environment, starts the
worker, waits for the exact dispatch name, starts the run, and always stops the
worker on completion, failure, or interruption. The three flags are
all-or-nothing. `--no-follow` is refused because the command must retain worker
custody until the run finishes.

## `egma monitoring`

Manages production monitoring for the repository's configured agent.

```bash
egma monitoring <enable|disable|status|record> [options]
```

| Option | Meaning |
|---|---|
| `--agent <name-or-id>` | Configured agent for ordinary actions; stable Egma agent ID for `record` |
| `--platform <retell\|livekit>` | Provider to enable when the repository cannot infer it |
| `--platform-agent <id>` | Exact Retell agent when the account has several |
| `--monitoring-key-id <id>` | LiveKit `record` recovery receipt |
| `--name <name>` | Agent name when monitoring creates the Egma agent row |

Retell enable reads the account key from standard input:

```bash
cat retell-key.txt | egma monitoring enable \
  --platform retell \
  --platform-agent agent_...
```

LiveKit enable mints an Egma project key and prints the two SDK environment
lines:

```bash
egma monitoring enable --platform livekit
```

It writes those lines to `.env` only when Git already ignores that regular
file. Otherwise it prints the deployment handoff without writing. Run status
after enable:

```bash
egma monitoring status [--agent <name-or-id>]
```

`disable` turns Retell polling off and keeps stored conversations, binding, and
sealed key. `record` is only for a receipt where remote setup succeeded but
`egma/config.yaml` could not be updated. It does not create another agent,
restart monitoring, or mint another key.

| Exit | Meaning |
|---|---|
| `0` | Requested action completed |
| `1` | Repository names no usable agent |
| `2` | Retell refused the key |
| `3` | Retell account has no voice agents |
| `4` | Egma was unreachable or refused the request |
| `5` | Platform or provider agent still needs a developer choice |
| `6` | No Retell key arrived on standard input |
| `7` | Not signed in |
| `8` | Monitoring setup was refused by a platform rule |
| `9` | Remote setup succeeded, but the local repository record failed |
| `130` | Interrupted |

## `egma self-host up`

Starts a complete Egma platform from an Egma source checkout:

```bash
npx --yes @egma/cli self-host up [--cwd <platform-workspace>]
```

The command starts Postgres, ClickHouse, MinIO, the API, web application,
simulator, grader, bundled LiveKit server, SIP gateway, and Redis. It reads the
operator's `.env`, creates internal credentials in
`.egma-platform/platform.env`, preserves existing database volumes, waits for
health, and prints the address for voice-agent repositories.

For optional phone simulations, the operator environment must contain all four
values or none:

```text
EGMA_PHONE_TRUNK_ADDRESS=example.pstn.twilio.com
EGMA_PHONE_SOURCE_NUMBER=+15551234567
EGMA_PHONE_TRUNK_USERNAME=egma-local
EGMA_PHONE_TRUNK_PASSWORD=...
```

| Exit | Meaning |
|---|---|
| `0` | Platform started and became healthy |
| `1` | No platform workspace, Docker, or usable command input |
| `4` | Environment, Docker state, service startup, or health check failed |
