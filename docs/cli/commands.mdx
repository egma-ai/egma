Every Egma command prints one fact per line and exits with a numeric code you can branch on. This makes every command safe to call from a CI pipeline, a shell script, or a coding agent — no screen-scraping required. Commands that need a real terminal (the interactive wizard) refuse piped or redirected input and tell you to pass `--headless` instead.

## Global flags

These flags work with every command.

| Flag | Description |
|---|---|
| `--coding-agent <id>` | Use one installed coding agent without asking: `claude`, `codex`, `cursor`, or `opencode` |
| `--cwd <path>` | The folder to operate in. Default: the current directory |
| `--url <address>` | Which Egma instance this command talks to. Overrides any value in `egma/config.yaml` |
| `--force` | With `login`: sign in again even when this machine already holds a key |
| `--no-follow` | With `run`: start the run and return immediately, without waiting for execution or grading |
| `--headless` | Run with no terminal interaction: plain output, and the coding-agent task treated as already agreed |
| `-h`, `--help` | Print the help text |
| `-v`, `--version` | Print the package version |

## Environment variables

Set these in your shell or CI environment to avoid repeating flags on every command.

| Variable | Description |
|---|---|
| `EGMA_HOME` | The folder Egma stores this machine's credentials in. Default: `~/.egma` |
| `EGMA_RETELL_API_KEY` | Your Retell API key for `egma connect`. `RETELL_API_KEY` is also accepted, so an environment that already exports it needs no change |
| `EGMA_RETELL_AGENT_ID` | Which Retell agent to register, equivalent to `--retell-agent` |
| `EGMA_REACH` | `text` or `phone`, equivalent to `--reach` |
| `EGMA_PHONE_NUMBER` | Which phone number to dial, equivalent to `--phone-number` |
| `EGMA_RETELL_URL` | The Retell API base URL. Default: `https://api.retellai.com` |
| `EGMA_EXISTING_TESTS` | Path to your existing test cases, equivalent to `--existing-tests` |

## Commands

<AccordionGroup>
  <Accordion title="egma — interactive wizard">
    Opens the full interactive wizard. It authorizes the CLI first, then finds your installed coding agents and asks which one to use. That coding agent discovers your voice agent. After discovery, the wizard asks for the setup goal: should Egma **test** the agent, **watch its production traffic**, or **both**.

    Testing connects the agent, generates a first test suite, and starts a run. Monitoring sets production capture up and ends there — no connection, no suite, no tests. Both sets monitoring up first and says so, then runs the whole testing lane in the same sitting: every shared question is asked once, one agent row serves both jobs, and the last screen points at the graded run and at Monitoring.

    The wizard draws on your terminal's alternate screen and follows the complete suite through execution and grading. Its results URL is clickable, and `[Enter]` opens it in your browser. When the wizard closes, it leaves the same plain URL and a summary in your normal terminal buffer, each item on its own line so a triple-click selects it whole.

    **Usage**

    ```bash
    npx @egma/cli [options]
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--url <address>` | Which Egma instance to use for this run |
    | `--coding-agent <id>` | Use one installed coding agent without showing the chooser: `claude`, `codex`, `cursor`, or `opencode` |
    | `--headless` | Run non-interactively; treats the task as already agreed |
    | `--existing-tests <path>` | Path to your existing test cases inside this folder. Your coding agent converts them to test files before generating new ones |
    | `--reach <text\|phone>` | Required in headless mode: how Egma should reach the agent |

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Completed successfully |
    | `130` | Stopped partway through (Ctrl-C) |

    <Note>
      The wizard requires a real terminal to display the consent keystroke. Pass
      `--headless` to run it in CI or from a script — this treats the coding-agent
      task as already agreed and produces plain line output.
    </Note>
  </Accordion>

  <Accordion title="egma login — sign this machine in">
    Signs this machine in to Egma. Opens a browser to a device-approval page pre-filled with a short code. Once you approve it, Egma stores a credential at `~/.egma/credentials` (or `$EGMA_HOME/credentials`), readable only by you.

    No secret is ever typed into the terminal. If the machine already holds a valid credential, `egma login` says so and exits without changing anything.

    **Usage**

    ```bash
    egma login [options]
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--url <address>` | Sign in to a specific Egma instance |
    | `--force` | Sign in again even when this machine already holds a key, replacing it |

    **Example output**

    ```
    url: http://localhost:3101
    code: WDJBMJHT
    approve_url: http://localhost:3101/device?user_code=WDJBMJHT
    browser: opened
    waiting: for this code to be approved in a browser
    status: stored
    credentials: /home/you/.egma/credentials
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Signed in successfully |
    | `2` | Approval was denied |
    | `3` | The device code expired before approval |
    | `4` | Egma did not answer, or refused the request |
    | `130` | Stopped partway through |

    <Tip>
      On a machine without a browser (SSH, devbox, container), press `[c]` during
      the wait and Egma copies the approval URL to your local clipboard. Approve it
      in a browser, then paste the full URL, the `?user_code=…` portion, or just
      the code — all three work.
    </Tip>
  </Accordion>

  <Accordion title="egma connect — register your voice agent">
    Registers your voice agent with Egma and creates a connection for running simulations. Reads a Retell API key from standard input or from the environment — never as a command-line argument, because arguments appear in process lists and shell history.

    Running `egma connect` twice against the same agent is safe. Egma detects the existing registration and reports whether it `created`, `reused`, or `connection_added` on the `registration:` line.

    **Usage**

    ```bash
    # Key on standard input
    cat retell-key.txt | egma connect [options]

    # Key from environment
    EGMA_RETELL_API_KEY=your_key egma connect [options]
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--reach <text\|phone>` | **Required** in non-interactive mode. For Retell, `text` selects a chat agent and the Chat API; `phone` selects a voice agent and a public number. |
    | `--retell-agent <id>` | Which Retell agent to register when the account holds more than one |
    | `--phone-number <e164>` | Which number to dial when `--reach phone` and the agent has more than one number |
    | `--repo-prompt <path>` | The prompt file in your repository, so Egma can report whether it and Retell have drifted apart |

    **Environment variables**

    | Variable | Equivalent flag |
    |---|---|
    | `EGMA_RETELL_API_KEY` | Retell API key (also `RETELL_API_KEY`) |
    | `EGMA_RETELL_AGENT_ID` | `--retell-agent` |
    | `EGMA_REACH` | `--reach` |
    | `EGMA_PHONE_NUMBER` | `--phone-number` |

    **Example output**

    ```
    url: http://localhost:3101
    retell_agents: 1
    retell_agent_id: agent_…
    retell_response_engine: retell-llm
    prompt_characters: 2140
    tools: 7
    reach: phone
    phone_number: +14155550111
    agent_id: agt_01K…
    agent_name: order-line
    connection_id: con_01K…
    connection_name: phone_number-1
    agent_platform: retell
    connection_type: phone_number
    access_variant: phone_number.public_e164
    product_label: Retell phone
    connection_modality: voice
    registration: created
    agent_registration: created
    connection_registration: created
    drift: no
    grounded_in: retell
    status: connected
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Connected successfully |
    | `2` | The Retell API key was refused |
    | `3` | No agents found on the Retell account |
    | `4` | Retell or Egma did not answer, or refused |
    | `5` | A required choice was not made: which agent, `text` or `phone`, or which number |
    | `6` | No API key was provided |
    | `7` | Not signed in to Egma |
    | `8` | Retell routes no phone number to that agent |
    | `130` | Stopped partway through |
  </Accordion>

  <Accordion title="egma init — create the egma/ folder">
    Creates the `egma/` folder structure in your repository. Everything `init` creates is safe to commit — nothing secret ever lands in the folder. Run it again safely at any time; it will not overwrite files that already exist.

    When you pass `--url`, `init` normalizes the address and records it in `egma/config.yaml`. It does not contact the platform. Every subsequent command run from this repository then finds the address automatically, with no `--url` flag required.

    **Usage**

    ```bash
    egma init [options]
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--url <address>` | Which Egma platform URL to bind this repository to. Egma writes the normalized URL to `egma/config.yaml` |
    | `--agent <name>` | What to call the voice agent this folder's tests are for |
    | `--connection <name>` | What to call the connection Egma uses to reach it |

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Folder created or already in good shape |
    | `4` | Egma did not answer, or refused (only when `--url` is passed) |
  </Accordion>

  <Accordion title="egma suite create — create a test suite">
    Creates a real suite on Egma before local test authoring starts. It then
    writes `egma/tests/<directory>/suite.yaml` with the stable suite ID and
    current name. The complete repository must be valid before the platform
    write.

    **Usage**

    ```bash
    egma suite create <directory> --name <name>
    ```

    **Example**

    ```bash
    egma suite create northside-ford --name "Northside Ford"
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Suite created and manifest written |
    | `1` | The repository or directory input is invalid |
    | `2` | Not signed in to Egma |
    | `4` | Egma did not answer, or refused |
    | `8` | The suite exists on Egma, but the local manifest write failed; pull to recover it |
  </Accordion>

  <Accordion title="egma pull — fetch Egma's test versions">
    Reads every active suite, test, and project Mock Tool from Egma. It plans
    and validates the complete local update before it writes. A failed later
    write restores earlier files and removes paths created by this pull.

    **Usage**

    ```bash
    egma pull [options]
    ```

    **Example output**

    ```
    url: http://localhost:3101
    folder: /repo/egma
    test: missed-appointment-reschedule
    file: egma/tests/receptionist-core/missed-appointment-reschedule.md
    version: tstv_01K…
    status: updated
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | All tests pulled successfully |
    | `1` | No `egma/` folder found |
    | `2` | Not signed in to Egma |
    | `4` | Egma did not answer, or refused |
    | `130` | Stopped partway through |
  </Accordion>

  <Accordion title="egma push — upload your tests">
    Uploads suite names, tests, and project Mock Tools as one all-or-nothing
    project change. It validates the complete repository first. A conflict in
    any item writes nothing.

    `push` refuses when Egma holds a version newer than the one your file last synced at. It names every conflicting file on a `conflict:` line, uploads nothing, and exits `5`. Run `egma pull` first, review what changed, then push again.

    **Usage**

    ```bash
    egma push [options]
    ```

    **Example output (conflict)**

    ```
    conflict: missed-appointment-reschedule
    file: egma/tests/receptionist-core/missed-appointment-reschedule.md
    uploaded: nothing
    status: refused
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | All tests pushed successfully |
    | `1` | No `egma/` folder found |
    | `2` | Not signed in to Egma |
    | `4` | Egma did not answer, or refused |
    | `5` | Push refused: Egma has moved on — run `egma pull` first |
    | `6` | Egma rejected a test (e.g. no expected behaviors) |
    | `130` | Stopped partway through |

    <Warning>
      Egma will not store a test with no expected behaviors — a test with none can
      never fail, which makes it meaningless. Fix the file and push again. Egma's
      refusal reason is printed verbatim.
    </Warning>
  </Accordion>

  <Accordion title="egma run — run your test suite">
    Runs every current test in one local suite directory against your connected
    voice agent. Each simulation records the exact test and persona versions it
    executed. The suite itself has no version or snapshot.

    Before starting, `egma run` checks that the selected suite has exactly the
    same active tests and current versions locally and on Egma. Missing, extra,
    stale, unreadable, or unpushed content refuses the whole run.

    **Usage**

    ```bash
    egma run <suite-directory> [options]
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--name <name>` | Optional display name for this run |
    | `--no-follow` | Start the run and return immediately, without waiting for execution or grading. The run continues on Egma |

    **Example output**

    ```
    url: http://localhost:3101
    folder: /repo/egma
    suite: ste_01K…
    agent: agt_01K…
    connection: con_01K…
    pin: quoted-a-price tstv_01K…
    pin: lost-the-order-number tstv_01K…
    run: run_01K…
    tests: 2
    simulations: 2
    results: http://localhost:3101/projects/prj_01K…/runs/run_01K…
    simulation: quoted-a-price Everyday caller running
    simulation: quoted-a-price Everyday caller completed
    grading: quoted-a-price Everyday caller pending
    grading: quoted-a-price Everyday caller complete
    first-result: quoted-a-price Everyday caller complete
    execution-finished: 2
    execution-failed: 0
    execution-canceled: 0
    grading-terminal: 2
    grading-complete: 2
    grading-not-requested: 0
    grading-errors: 0
    grading-pending: 0
    grading-running: 0
    simulations: 2
    status: completed
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Execution and grading became terminal with no system error. Grade scores do not change this code |
    | `1` | The selected suite has no tests, or the local suite is invalid |
    | `2` | Not signed in to Egma |
    | `4` | Egma did not answer, or refused |
    | `5` | Egma refused to start the run (reason printed) |
    | `6` | A simulation execution, grader, or terminal grading job errored |
    | `130` | Stopped partway through |

    <Note>
      Without `--no-follow`, `egma run` waits until every simulation has
      terminal execution and every completed trace has terminal grading. A low
      score never makes the command exit with a non-zero code. Execution and
      grading system errors do.
    </Note>
  </Accordion>

  <Accordion title="egma monitoring — watch production traffic">
    Starts, stops, and reports Egma's capture of an agent's real production
    conversations. It runs the same work the wizard's monitoring lane runs, with
    no questions and one fact per line.

    Which agent this is about comes from `egma/config.yaml`, so an onboarded
    repository needs no arguments. Which platform runs it is read from the
    agent's own binding, or from the connections that reach it — and refused in
    plain words when Egma cannot tell.

    **Usage**

    ```bash
    # Retell: the account key on standard input, never as an argument
    cat retell-key.txt | egma monitoring enable --platform retell

    # LiveKit: mints a project key and writes the two SDK environment lines
    egma monitoring enable --platform livekit

    egma monitoring status
    egma monitoring disable

    # Retell recovery: record an already-monitored target in this repository
    egma monitoring record --agent agt_01K…

    # LiveKit recovery: also prove the active worker key from the receipt
    egma monitoring record --agent agt_01K… --monitoring-key-id key_01K…
    ```

    **Key flags**

    | Flag | Description |
    |---|---|
    | `--agent <name-or-id>` | A configured agent for ordinary actions; the stable Egma agent id from the receipt for `record` recovery |
    | `--platform <retell\|livekit>` | Which platform runs this agent. Left out, Egma reads it from the repository's own binding |
    | `--platform-agent <id>` | Which agent on the Retell account to watch, when it holds more than one |
    | `--monitoring-key-id <id>` | With LiveKit `record`: the non-secret worker-key id from the failed setup receipt |
    | `--name <name>` | What to call the agent Egma writes, when it writes one |

    On **Retell**, one commit registers the agent if Egma does not have it yet,
    seals the key onto that agent's row, and turns the switch on. `enable` asks
    once whether anything has arrived and does not wait; `status` is where
    arrivals are read afterwards.

    On **LiveKit** there is no switch — a worker pushes its own evidence. The
    command mints a project API key, writes the two environment lines the Egma
    SDK reads into `.env` when Git already ignores that file, and prints them
    either way for wherever the worker really runs. Running it again replaces
    those lines in place rather than adding a second copy. The code edit itself
    belongs to your coding agent: see the `integrate-egma` skill.

    `disable` turns the switch off and keeps everything stored — the
    conversations, the platform binding, and the sealed key.

    `record` is the safe recovery path after remote setup succeeded but
    `egma/config.yaml` could not be updated. It reads the existing Egma agent
    and writes only the repository catalog. It does not create another agent,
    restart monitoring, or mint another key.

    **Example output**

    ```
    url: http://localhost:3101
    platform: retell
    agent_id: agt_01K…
    agent_name: order-line
    platform_agent_id: agent_…
    agent_registration: created
    pull_production_calls: on
    first_conversation: none-yet
    status: watching
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Done |
    | `1` | Nothing here to act on: this repository names no agent |
    | `2` | The Retell key was refused |
    | `3` | No voice agents on that Retell account |
    | `4` | Egma did not answer, or refused |
    | `5` | A required choice was not made: which platform, or which agent |
    | `6` | No API key was provided |
    | `7` | Not signed in to Egma |
    | `8` | Egma would not start watching, and said which rule refused it |
    | `9` | Remote monitoring is ready, but its repository record did not finish; the receipt and any LiveKit environment lines were still printed |
    | `130` | Stopped partway through |

    <Note>
      A refusal prints two `reason:` lines: Egma's own sentence about what to do,
      and the platform's own for whatever is reading rather than looking.
    </Note>
  </Accordion>

  <Accordion title="egma self-host up — start a local Egma instance">
    Starts a full local Egma instance using Docker Compose: Postgres, ClickHouse, the API, the web UI, the simulator, the grader, and (for phone simulations) a LiveKit server, SIP gateway, and Redis. Run this from your Egma platform checkout, not from your agent repository.

    The command reads external model-provider keys and the optional
    `EGMA_PHONE_*` carrier route from `.env`. It generates internal auth,
    encryption, simulator, bundled-MinIO, and LiveKit credentials once in
    `.egma-platform/platform.env`, then preserves them. Compose supplies safe
    local defaults.

    The four phone values are ordinary deployment credentials and are not
    stored in Postgres. Supply all four or none. For Twilio, use the SIP
    credential-list username and password, never the Account SID and Auth Token.

    After the stack is up, the command prints the address to point your agent
    repository at. Phone readiness is checked when a phone run is created.

    **Usage**

    ```bash
    # From your Egma platform checkout
    npx @egma/cli self-host up
    ```

    **Exit codes**

    | Code | Meaning |
    |---|---|
    | `0` | Instance started successfully |
    | `4` | Docker or a required service did not start |
  </Accordion>
