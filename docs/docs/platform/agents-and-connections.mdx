---
title: "Agents and connections"
---

An **agent** is the voice agent you test or monitor. Register it in your Egma
project to give its connections and production conversations one identity.
Egma supports LiveKit and Retell agents.

A **connection** tells Egma how to reach that agent for a simulation. It
selects the access method and whether the conversation uses voice or chat.
An agent can have more than one connection. Each run uses one connection
that belongs to its selected agent.

## Connect an agent

1. [Install the CLI and sign in](/skills-cli-sdks/cli/install#sign-in-and-initialize), or use
   the [Integrate Egma skill](/skills-cli-sdks/skills/integrate-egma).
2. Register the agent in your project.
3. Add a connection with the provider settings required by your platform.
4. Use the agent and connection IDs when you [start a run](/docs/platform/runs/start-and-follow-a-run).

Follow the complete setup for [Retell](/docs/integrations/retell) or
[LiveKit](/docs/integrations/livekit). For LiveKit, the worker needs the Egma SDK's
simulation hook before it can take part in an Egma simulation.

## Monitor the agent

Production monitoring has its own setup. Retell uses a stored provider
binding to import completed voice calls. LiveKit uses the SDK's monitoring
hook in the worker. You do not need a test suite or simulation connection to
collect production conversations.

[Set up monitoring](/docs/platform/monitoring/set-up-monitoring) for your platform.
