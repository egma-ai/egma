---
title: "Add a persona"
---

Use a built-in persona with its defaults, create a custom persona, or clone an
existing persona with changes. Saved personas are read-only.

## Use an existing persona

<Tabs>
  <Tab title="UI">
    Open **Tests**, select a suite, and edit a test's **Personas** cell. Choose
    the persona and select **Done**. For a new test, complete the other fields
    and select **Save test**.

    You can use a built-in persona directly. Its declared defaults supply its
    models, voice, language, and controls.
  </Tab>
  <Tab title="CLI">
    List the personas available to the repository's project:

    ```bash
    egma persona list
    ```

    Use a built-in persona with its declared defaults:

    ```bash
    egma persona use prs_...
    ```

    Add its name to your test's front matter:

    ```yaml
    personas:
      - name: Everyday Caller [Male]
    ```

    Every test must name at least one persona. Each additional persona creates
    another simulation for that test in a run.

    On push, Egma resolves a name to its persona ID. Pulled files include that
    ID. Keep it when you edit the test. If two personas have the same name, use
    the ID from `egma persona list`.
  </Tab>
  <Tab title="API">
    [List personas](/api-reference/list-personas), then [use a
    persona](/api-reference/use-persona) to add a built-in with its declared
    defaults. Use the returned ID or an unambiguous name in a test.
  </Tab>
</Tabs>

## Create a custom persona

<Tabs>
  <Tab title="UI">
    1. Open **Personas** and select **New persona**.
    2. Choose **Cascaded** or **Live**, then select **Next**. This choice cannot
       change after you create the persona.
    3. Enter a **Name** for your team, such as `Caller in a hurry`.
    4. Set **Identity name** to the name the caller gives the agent, such as
       `Morgan Chen`.
    5. Write a **Personality** that describes how the caller acts. For example:
       `Answers briefly, asks for the earliest appointment, and asks the agent
       to get to the point if it repeats a question. Remains polite.`
    6. Choose the models, voice, language, and background sound for that mode.
    7. Select **Create persona**, then add the persona to a test.

    Keep the caller's goal in the test scenario. Keep lasting traits in the
    persona. The library **Name** is for your team. **Identity name** is what
    the agent hears.
  </Tab>
  <Tab title="CLI">
    For Cascaded mode, select the reasoning model, STT model, TTS model, voice,
    language, background sound, and interruption level:

    ```bash
    egma persona create \
      --name "Caller in a hurry" \
      --identity-name "Morgan Chen" \
      --personality "Answers briefly and asks the agent to get to the point." \
      --speech-mode separate \
      --llm-provider openai \
      --llm-model gpt-5.6-terra \
      --stt-provider openai \
      --stt-model gpt-4o-mini-transcribe \
      --tts-provider openai \
      --tts-model gpt-4o-mini-tts \
      --voice alloy \
      --language en-US \
      --background-sound none \
      --interruption-level occasional
    ```

    Run `egma persona capabilities --help` to read the available voice and
    language filters before you create the persona.
  </Tab>
  <Tab title="API">
    Use [Create a persona](/api-reference/create-persona). Send the complete
    models and controls for the selected mode. Read [Get persona authoring
    choices](/api-reference/get-persona-form) and [Resolve persona
    capabilities](/api-reference/get-persona-capabilities) for current choices.
  </Tab>
</Tabs>

## Choose a speech mode

**Cascaded** uses separate STT, reasoning, and TTS models. You also select a TTS
voice and an interruption level: `none`, `occasional`, or `frequent`.

**Live** uses OpenAI `gpt-live-1` for the continuous voice conversation. You
select its OpenAI voice. The separate **Reasoning model** still handles
reasoning, delegation, and the decision to end the call. Live has no STT, TTS,
or interruption setting.

Both modes have a language and a background sound. Egma mixes the selected
background at a fixed -12 dB gain. There is no background volume setting.
Speech uses the provider's normal speed and volume.

Run a full simulation to hear the persona and check turn timing. Text
simulations use the persona's identity, personality, language, and reasoning
model without calling a speech service.

## Clone with changes

Saved personas cannot be edited. Clone one when you want to change its
behavior, models, voice, language, background, or Cascaded interruption level.
The source and tests that select it stay unchanged.

<Tabs>
  <Tab title="UI">
    Open the persona's menu and select **Clone**. Make changes in the draft,
    then select **Clone persona**. Canceling the draft creates no persona.
  </Tab>
  <Tab title="CLI">
    Pass only the values that you want to change:

    ```bash
    egma persona clone prs_... \
      --name "Caller in a hurry, Spanish" \
      --language es-ES
    ```

    Omitted values copy the source. The clone keeps the source speech mode.
  </Tab>
  <Tab title="API">
    Use [Clone a persona](/api-reference/fork-persona). Clone overrides are
    optional and apply in the request that creates the clone. Omitted fields
    copy the source. If you supply settings, send `models` and `controls`
    together as complete objects for the source mode.
  </Tab>
</Tabs>

## Delete a custom persona

You can delete a custom persona if you no longer want it in authoring lists and
pickers. Built-in personas cannot be deleted. Existing run evidence and frozen
persona versions stay readable.

<Tabs>
  <Tab title="UI">
    Open the custom persona's menu, select **Delete**, and confirm the deletion.
  </Tab>
  <Tab title="CLI">
    ```bash
    egma persona delete prs_...
    ```
  </Tab>
  <Tab title="API">
    Use [Permanently delete a persona from
    authoring](/api-reference/delete-persona).
  </Tab>
</Tabs>
