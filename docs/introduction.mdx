Egma is an open-source platform that helps teams gain trust in the voice agents they ship to production. It combines simulation testing — where a synthetic persona holds real conversations with your agent before any customer does — with platform-specific production monitoring and automatic grading. The result is a continuous feedback loop: test before you ship, observe after you ship, and compare trace grades when behavior changes.

## What Egma is for

Voice agents are hard to test with unit tests alone. The behavior that matters emerges from the full conversation loop — the prompt, the speech stack, the tools, and the real-time interaction between all three. Egma is built around that reality.

**Simulation testing** lets you group Markdown scenarios into test suites, then
run one complete suite as real conversations against your agent. The simulator
conducts each test and produces a recording and a transcript. The Expected
behaviors grader checks each behavior statement, keeps its evidence in the
details, and returns one normalized score for the completed simulation.

**Production monitoring** starts with the agent platform. For Retell voice agents, Egma polls the selected agents after conversations finish. For LiveKit Agents, the Egma Python SDK configures OpenTelemetry export inside the running agent. Both paths produce production conversation records. Egma shows a transcript, observed metrics, and grades when a project grader applies. Simulation recordings stay with the run that Egma conducted.

## How it works

Egma is organized around three internal services that you never configure directly, but that are worth understanding at a high level.

**The simulator** conducts conversations. It claims test work from the control plane, picks up the persona and scenario for each test, and holds a real exchange with your agent — through a Retell Chat connection, a LiveKit room, or a Phone connection over a SIP trunk. It streams every turn, tool call, and timing as OpenTelemetry spans to Egma's own ingest, so simulated and production conversations land in the same store and are read by the same tools.

**The grader** grades completed traces. A simulation is eligible after it
finishes and its trace evidence is visible. A production trace is eligible only
after a supported platform reports its explicit conversation-end event and the
evidence is visible. One temporary job holds all selected project graders for
that trace. Each grader writes one grade. More workers can claim separate jobs
in parallel.

**Production ingestion** receives evidence two ways. Egma pulls: for an agent whose **pull production calls** switch is on, it reads that agent's completed conversations from Retell with the agent's own key and removes access tokens and authentication header values before storage. Or the agent pushes: a LiveKit Agents worker sends spans through Egma's OTLP endpoint with a project API key. Both paths meet in the same trace store, transcript reader, measure code, and production grading path.

## Integrations

Egma works with the two most common voice agent platforms today.

**Retell** is an agent platform with two simulation paths. `egma connect` reads
the selected agent's modality. A chat agent uses the Retell Chat API. A voice
agent uses a public phone number. Production monitoring is separate: enter one
Retell API key when you start monitoring an agent, and Egma polls that Retell
agent's completed conversations for as long as the agent's switch is on.

**LiveKit Agents** can use a LiveKit room or a public phone number for simulations. A room connection can use project credentials or a customer token endpoint. Production monitoring is separate again: call `monitor_livekit(ctx)` in the Python agent before `AgentSession.start`, whether the agent is customer-hosted or hosted in LiveKit Cloud.
