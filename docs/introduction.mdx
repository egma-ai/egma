Egma is an open-source platform that helps teams gain trust in the voice agents
they ship. It combines simulation testing before release with production
monitoring after release, then applies the same trace, metric, and grading model
to both kinds of evidence.

## What Egma tests

Voice-agent behavior emerges from a full conversation: the prompt, model,
speech stack, tools, external systems, and the person on the other side. Unit
tests cannot prove that complete path.

An Egma **test** is a Markdown scenario, one or more personas, and the expected
behaviors for that situation. Tests live in repository-owned **test suites**. A
**run** executes one complete suite against one selected agent and connection.
Each test-persona pair produces one **simulation**.

The simulator conducts the conversation and records the resulting trace. Voice
simulations can include a recording; chat simulations do not. The Expected
behaviors grader checks each authored behavior against trace evidence and
returns one normalized score with assertion details.

## What Egma monitors

Production monitoring records real conversations without turning them into
simulations.

- For Retell, Egma polls the selected Retell agent for completed calls while its
  **pull production calls** switch is on.
- For LiveKit, the Egma Python or JavaScript SDK configures OpenTelemetry export
  in the running worker. The worker pushes its own production evidence to Egma.

Both paths produce production conversation records. Egma shows the transcript,
supported metrics, and grades when project graders apply. Egma keeps provider
credentials separate from simulation connection credentials.

## How the services fit together

**The simulator** claims test work, loads the selected scenario and persona,
and reaches the voice agent through a configured connection. Current paths
include Retell text mode, Retell web call, a LiveKit room, and a public phone
number.

**The trace store** receives turns, tool calls, timing, and completion evidence
from simulations and production integrations. Both evidence paths use the same
transcript and metric readers.

**The grader** evaluates eligible completed traces. Each selected grader writes
one grade with a score, threshold, details, and derived result. Operational
grading failure is separate from a low score.

## Agents and connections

An **agent** is Egma's stable record of the voice agent under test. A
**connection** is one way the simulator can reach it. One agent can have several
connections, such as Retell text mode and a public phone number, while keeping
one run history.

Monitoring belongs to the agent, not to a connection. Enabling or disabling
monitoring never creates or changes a simulation connection. See
[Agents and connections](/concepts/agents-and-connections) for the exact
platform, connection type, access variant, modality, and product-label model.

## Integrations

**Retell** offers three simulation lanes: text, a web call Egma places over the
internet, and a real phone number. The coding agent uses
`egma connect --platform retell --show-context` so it can ground the first tests
in the prompt and tools Retell actually runs. Production monitoring uses
Retell's call-history APIs.

**LiveKit** uses room connections with project credentials or a customer token
endpoint. The coding agent grounds setup in committed worker source. Python and
JavaScript workers support simulation testing. For Python, `egma run` can own a
repository-local worker. Production monitoring calls `monitor_livekit(ctx)` in
Python or `monitorLiveKit(ctx)` in JavaScript before `AgentSession.start`.

## How setup works

Run the bare CLI in the voice-agent repository. It prints the public skill
install command and the handoff for your current coding agent. It performs no
setup itself.

```bash
npx --yes @egma/cli
```

The coding agent uses the `integrate-egma` skill and named promptless commands.
It starts `egma login`; you approve the request in a browser. It then performs
read-only discovery, resolves the exact target from repository and CLI facts,
authors and validates local files, publishes and runs when requested, and
confirms monitoring status. It asks only for a missing human input, an unsafe
conflict, or approval before a real phone run that can cost money.
