The `@egma/livekit` package has two independent helpers:

- `await mockable(agent, ctx, session)` lets Egma answer selected tools during
  a simulation.
- `monitorLiveKit(ctx)` sends production LiveKit spans to Egma Monitoring.

Calling one helper does not enable the other.

## Install

```bash
npm install @egma/livekit
```

The package needs Node.js 22 or newer.

| Helper | Supported `@livekit/agents` versions |
|---|---|
| `mockable` | `>=1.5.0 <1.8` |
| `monitorLiveKit` | `>=1.5.5 <1.8` |

LiveKit `1.5.0` is the first stable JavaScript release with its public mock-tool
hook. LiveKit `1.5.5` is the first release with the public telemetry bridge
needed to keep LiveKit Cloud and Egma export active together. `1.6.4` is tested
for Rentlyx compatibility, but it is not the minimum.

## Use mock tools in simulations

Create the agent and session, then call `mockable` once before `session.start`:

```typescript
import { mockable } from "@egma/livekit";
import { type JobContext, voice } from "@livekit/agents";

export async function entrypoint(ctx: JobContext) {
  const isEgmaChat =
    ctx.job.room?.name?.startsWith("egma-sim-chat-") ?? false;
  const agent = voice.Agent.create({
    instructions: "Help the caller.",
    tools: [checkCalendar, bookAppointment],
  });
  const session = new voice.AgentSession({ stt, llm, tts });

  await mockable(agent, ctx, session);
  await session.start({
    agent,
    room: ctx.room,
    ...(isEgmaChat
      ? {
          inputOptions: { audioEnabled: false },
          outputOptions: {
            audioEnabled: false,
            syncTranscription: false,
          },
        }
      : {}),
  });
}
```

The `egma-sim-chat-` branch keeps chat simulations on LiveKit's text path.
Keep independent audio publishers off in that branch too. Other room names use
the worker's normal voice settings.

In a simulation, `mockable`:

1. Connects the worker to the room if it is not connected.
2. Finds the one Egma participant.
3. Reports the agent's real tool names and schemas.
4. Installs LiveKit mock couriers only for the names Egma covers.
5. Follows later agent handoffs in the same session.
6. Removes all mock state when the session closes or the job stops.

Tools without a mock keep their real implementation. If Egma becomes
unreachable during a tool call, that real implementation runs. If Egma receives
the call and refuses it, the model sees a `ToolError`; the SDK does not hide an
explicit refusal by causing a real side effect.

### Production safety and process isolation

The first check reads only `ctx.job.room.name`. Every Egma simulation room
starts with `egma-sim-`. In any other room, `mockable` returns before it
connects, sends a message, or changes a tool.

LiveKit Agents runs each normal job in its own child process. Its JavaScript
mock table is process-wide, so Egma permits one active mockable session in that
job process. A second overlapping session gets a direct error instead of
sharing or replacing the first session's mock state. Separate calls run in
separate child processes and do not share it.

Egma joins the simulation room as `egma-persona` or
`egma-persona-<simulation id>`. The room name and participant forms are fixed,
published protocol values. Refuse the reserved `egma-sim-` prefix in any system
that mints your production room names.

## Monitor production LiveKit agents

Open **Agents → Connect an agent** and copy the **Monitoring** or **Both** prompt
into the coding agent working in the repository. It installs the package,
changes the worker, and uses the current CLI to create the key and environment
handoff.

For manual setup, create a project API key in **Settings → API keys**. Set the
API origin and key where the worker runs:

```bash
export EGMA_URL=https://api.egma.ai
export EGMA_API_KEY=egma_sk_...
```

For self-hosted Egma, use the published API address that the agent process can
reach, such as `http://localhost:3100` when the worker runs on the same host.

For a LiveKit Cloud deployment, put the values in a gitignored secrets file and
run:

```bash
lk agent update-secrets --secrets-file=.env.monitoring
```

Call `monitorLiveKit` before `AgentSession.start`:

```typescript
import { monitorLiveKit } from "@egma/livekit";
import { type JobContext, voice } from "@livekit/agents";

export async function entrypoint(ctx: JobContext) {
  monitorLiveKit(ctx);

  const agent = voice.Agent.create({
    instructions: "Help the caller.",
    tools: [checkCalendar],
  });
  const session = new voice.AgentSession({ stt, llm, tts });
  await session.start({ agent, room: ctx.room });
}
```

You can pass configuration directly:

```typescript
monitorLiveKit(ctx, {
  endpoint: "https://api.egma.ai",
  apiKey: projectKey,
});
```

The helper adds an OTLP/HTTP protobuf batch exporter and flushes its last batch
when the job stops. It keeps LiveKit Cloud observability active. If another
integration installed a provider without a safe way to add a processor, setup
stops with a direct error instead of replacing it.

After deployment, the first production conversation appears under
**Monitoring** when the worker sends its spans. Egma cannot see a DNS, firewall,
or network failure inside the worker. If nothing appears, check the worker logs
and confirm it can reach `EGMA_URL`.

`monitorLiveKit` also reads the room name first. It returns in an
`egma-sim-` room so that simulation spans do not also appear as a production
conversation.
