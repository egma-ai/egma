Retell is an **agent platform**, not one connection type. Egma registers Retell
voice agents and can create several simulation connections on one Egma agent.
Production monitoring is a separate agent-level setup.

| Purpose | Path | Connection | What the test's world does here |
|---|---|---|---|
| Simulation | Text | `retell_text_mode` | The test's mock tools ride every request; its `retell_dynamic_variables` ride with them |
| Simulation | Web call | `retell_web_call` | The test's mock tools are routed to Egma per call; its `retell_dynamic_variables` ride on the call |
| Simulation | Phone | `phone_number` | Neither. The call reaches your real tools, and the run says so |
| Production monitoring | Retell call-history polling | No simulation connection | Not applicable |

**Only what a test names is mocked. Every other tool runs for real**, against
your own backend, on every lane. A test that names no mock tool runs against
your serving agent exactly as a caller does. See
[Test files](/cli/test-files) for how a test writes them.

## Before setup

The public `integrate-egma` skill is still being authored. Follow this page
directly for now. The coding agent traces the Retell response-engine boundary,
prompt, tools, provider identifier location, and production path from committed
source before it asks to create anything.

The developer chooses testing, monitoring, or both in the integration request.
That request authorizes the normal remote setup. The coding agent finds the
exact Retell agent, simulation Connection, suite, and monitoring target. It asks
only when a required credential is missing, a choice is ambiguous, or a
conflict is unsafe.

The coding agent starts browser-approved Egma login when needed:

```bash
egma login
egma init
```

`init` binds this repository to an existing Project and pulls its current
Agents and Connections into `egma/config.yaml`.

## Connect a Retell agent for simulations

Agent registration and Connection creation are separate. First check
`egma/config.yaml`. If the target is absent, register only its Egma identity:

```bash
egma agent register --platform retell --name "Front desk"
```

The command accepts no Access, Modality, Retell Agent ID, or provider key. It
prints the stable Egma Agent ID and refreshes `egma/config.yaml`.

Next, list the Retell Agents, their stable provider IDs, attached phone numbers,
and current Connection shapes:

```bash
EGMA_RETELL_API_KEY=... \
  egma agent connection options --platform retell
```

This command is read-only. It lists provider Agents and phone numbers once,
then prints one reusable `agent connection add` shape per supported
Connection.

Add each requested Connection separately. A chat text-mode Connection uses:

```bash
EGMA_RETELL_API_KEY=... \
  egma agent connection add \
  --agent agt_... \
  --access retell-api-key \
  --modality chat \
  --retell-agent agent_...
```

Use `--modality voice` with the same `retell-api-key` Access for a web call.
Use the exact routed number for a phone Connection:

```bash
egma agent connection add \
  --agent agt_... \
  --access retell-phone-number \
  --modality voice \
  --retell-phone-number +14155550111
```

The first Retell Connection binds the selected provider Agent to the Egma
Agent. Later Retell Connections reuse that binding and the stored key. Access
and Modality are always explicit, and the platform comes from the selected
Egma Agent.
If the phone Connection is first, include `EGMA_RETELL_API_KEY` and
`--retell-agent` exactly as in the first example.

Send the provider key through `EGMA_RETELL_API_KEY` or as one JSON object on
standard input. Never put it in a flag. When a coding agent starts the CLI as a
child process, it can pass `--credentials-stdin` and write
`{"apiKey":"..."}` directly to that process. It must not build a shell command
that contains the key.

Egma seals the key on the platform. It never writes the key to
`egma/config.yaml`, an environment file, or terminal output.

### Retell text mode

Egma exchanges messages with the Retell voice agent in text. Egma places no call,
so a suite can finish quickly. The connection stores the Retell agent ID and a
sealed API key.

Its public CLI choices are Access `retell-api-key` and Modality `chat`.

A custom LLM that keeps its words and tools outside Retell prevents text mode.
The command reports the compatible Connection and creates nothing.

### Retell web call

Egma places a voice call over the internet. It does not dial the published
phone number. The connection stores the Retell agent ID and a sealed API key.

Its public CLI choices are Access `retell-api-key` and Modality `voice`.

Whether a simulation is mocked is a fact of the test it runs: a test that names
mock tools is mocked here, and a test that names none is placed against your
serving agent. The connection itself holds no such setting. See
[How a mocked web call reaches Egma](#how-a-mocked-web-call-reaches-egma).

### Retell phone

Egma reads the phone numbers routed to the selected Retell agent, then records
the exact selected public E.164 number. The saved connection does
not need a Retell agent ID or key to place a later call.

Its public CLI choices are Access `retell-phone-number` and Modality `voice`.

Phone simulations reach the real public number and real tools. **The phone lane
never mocks**, and it carries no dynamic variables of a test's. A run over a
phone connection whose tests carry either still runs, and the run says which
tests reach real tools. Before every phone run, the coding agent must state the
suite, target, and expected simulation count, warn that real calls can cost
money, and obtain fresh run approval.

The Egma deployment needs a complete telephony route before Egma can start a
phone simulation.

## Connection identity and custody

`agent register` creates Agent identity. `agent connection add` adds one
Connection to that explicit Agent. The CLI refreshes the stable Agent and
Connection IDs in `egma/config.yaml` after each successful remote write.

If the remote write succeeds but the local refresh fails, the CLI prints the
new remote ID and tells the coding agent to run `egma pull`. It does not expose
a public retry key or ask the coding agent to repeat the write.

The stored Retell key wins over any stale value in the shell, so adding a later
Connection cannot rotate it silently. Retell discovery and Connection setup do
not write to the Retell account.

## Which version a run tests

Every simulation over a Retell connection is conducted against one version of
your agent, and Egma resolves that version once, when the run starts. It reads
the phone numbers routed to the agent first: where a number is bound to a
version or to an environment tag, Egma follows that binding, because that is
the agent your callers reach. Where no number names a version, Egma uses the
**latest published** version — never the latest draft, so a version you are
still editing is never what a suite grades. An agent with no published version
and no number naming one is refused, and the run does not start. Publish the
version you want tested, or pin a Retell phone number that routes to the agent
to a version or an environment tag.

Egma names the resolved version number on every request of that run, so an edit
you make while the run is in flight cannot change what it is testing, and the
run record carries that number — which is how a result read months later still
says which version of the agent it speaks for.

## How a mocked web call reaches Egma

Retell calls the tool URLs written in your agent's configuration, so Egma routes
a mocked call through that configuration. It decides which tools come to Egma
per call, on one temporary version.

**One temporary version per run.** At run start, and only when at least one
test in the run names a mock tool, Egma branches one temporary version of your
agent. Every custom tool's URL on it becomes its own per-call variable followed
by your original URL, byte for byte — `{{egma_url_book_appointment}}` in front
of what you wrote, your own variables inside it included. **Headers and query
parameters are left exactly as they are**, because that same version also
serves the tools your tests do not name, and those calls must authenticate as
production does. Each routing variable is written with a single-space default.
Egma reads the version back and refuses the run if a default came back trimmed.

**Egma decides per call.** On every call it creates, Egma passes every routing
variable explicitly: the address of Egma's own endpoint for the tools this
simulation's test names, and the empty string for every other tool. An empty
value renders to nothing and leaves your own URL exactly as you wrote it, so
**an unmocked tool goes straight to your backend and never reaches Egma**. The
mocked address ends in `#`, so your original URL trails behind it as a fragment
that no HTTP client sends.

**Your serving version is never changed.** The temporary version is a branch.
Simulations of tests that mock are placed against it; a test that names no mock
tool is placed against your serving version, the one a real caller reaches,
even inside a run that branched a copy.

**Two things Egma never intercepts.** Retell's built-in actions — transfer,
SMS, digit press, end call, its own booking — run inside Retell's own
infrastructure, and MCP tools are reached over their own protocol. Neither is a
webhook with a URL, so both run for real on every simulation, mocked or not.

**Before it writes anything, Egma can refuse the run.** Two custom tools whose
names would route through one variable, or a tool whose routing variable name
you already use as a dynamic variable of your own, both make a call land
somewhere nobody chose. Egma writes nothing, stops, and names the tools to
rename.

### What a mocked run leaves behind

Egma deletes the temporary version when the run ends, and reads the account back
to prove it is gone. Deleting it leaves one thing: Retell keeps the unused copy
of the response engine that version ran on, and offers no way to delete just
that copy. Nothing can route callers to it — a phone number or a tag can only
point at a live agent version — and it does not appear in the Retell dashboard.
Egma records its version number on the run so you can see exactly what was left.

While a mocked run is in flight the temporary version is your agent's Latest
Created version. Make sure no phone number or tag sends real callers to Latest
Created; leaving a number's version unset means Latest Created too.

### Dynamic variables per test

A test's `env` carries `retell_dynamic_variables`: the values Retell
substitutes into the agent's prompt and tool configuration for that call, as
text. Egma passes them on every text-mode request and on every web call it
creates, so one test is a known caller and another is a stranger without
touching your agent.

**The `egma_` prefix is reserved.** Egma's own routing variables are named
`egma_url_<tool>`, and they ride the same per-call variable set, so a test that
names a variable beginning `egma_` is refused when it is saved. Name the
variable something your own prompt uses.

## Author and run tests

After connection setup, the coding agent follows the normal end-to-end sequence:

```bash
egma persona list
egma suite create receptionist-core --name "Receptionist core"
# write and review the smallest grounded test set
egma push
egma run create receptionist-core \
  --agent agt_... \
  --connection con_...
```

If the project already has remote suites, run `egma pull` before creating a new
one. Push validates the complete local repository. `run create` pushes again
before it starts, then prints the Run ID and web results URL and returns. The
end-to-end prompt already asks for publish and a non-phone Run.

## Enable Retell production monitoring

Simulation connections tell Egma how to contact an agent during a test.
Monitoring tells Egma to import real Retell calls after they finish. A
monitoring-only integration does not create a connection, suite, tests, or run.

Use the explicit Egma Agent ID and platform. When the Agent already has a
Retell Connection, setup reuses its stored provider identity and key:

```bash
egma agent monitoring setup \
  --agent agt_... \
  --platform retell
```

For a monitoring-only path, first register the Egma Agent identity. Then supply
the Retell Agent ID and one-time key during monitoring setup. A coding agent
can start this command as a child process and write `{"apiKey":"..."}` directly
to its standard input:

```bash
egma agent monitoring setup \
  --agent agt_... \
  --platform retell \
  --retell-agent agent_... \
  --credentials-stdin
```

The command needs Retell **Agent Read** permission for discovery and **Monitor
or History Read** permission for call history. Egma seals the key on the Agent
and never returns it.

Stop future call pulls while keeping imported conversations and traces:

```bash
egma agent monitoring stop \
  --agent agt_... \
  --platform retell
```

One Egma agent watches one Retell agent. Egma refuses a second binding to the
same Retell agent and names the existing target. The CLI has no monitoring
status command or inferred health timer.

## What Retell monitoring imports

For each watched agent, Egma:

- imports the previous 30 days when monitoring starts;
- checks for new terminal calls about every 30 seconds;
- rereads a five-minute overlap on every check so it catches late arrivals;
  and
- stores one production conversation per Retell call even when an import page
  or historical window needs another attempt.

There is no daily full-history rescan. Resuming monitoring starts observation
from that time; Egma does not backfill calls made while monitoring was off.

If Retell cannot supply one complete call, Egma retries a few times, records the
loss in operational logs and counters, and continues with later calls. Egma
still records a call with no transcript, but transcript-based metrics and
graders have no input.

The provider endpoints have independent versions:

| Purpose | Retell endpoint |
|---|---|
| List agents during setup | `POST /v2/list-agents` |
| List phone numbers for simulation setup | paginated `GET /v2/list-phone-numbers` |
| List completed production conversations | `POST /v3/list-calls` |
| Read one complete conversation | `GET /v2/get-call/{call_id}` |

The v3 list response does not contain the complete transcript. Egma follows its
opaque pagination key and reads each new call through Get Call before
normalization.

## What appears in Monitoring

Each imported call keeps its Retell conversation ID and the Retell agent ID,
name, and version when Retell supplies them. Safe provider facts, such as call status and
`phone_call` or `web_call`, remain in the provider payload. Egma omits Retell
access tokens and named authentication-header values before storage.

A Retell `recording_url` can remain in the safe payload, but the current
Monitoring UI does not expose a production recording player. The same trace
store reconstructs transcripts, tool calls, supported metrics, and production
grader work for Retell and LiveKit.

See [Monitoring API](/api/monitoring) for the monitoring source request shapes.
