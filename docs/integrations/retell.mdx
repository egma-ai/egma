Retell is an **agent platform**. It is not one connection type. Egma supports
two Retell simulation paths and one separate production Monitoring strategy:

| Purpose | Retell agent | Egma path |
|---|---|---|
| Simulation | Chat agent | Retell Chat API |
| Simulation | Voice agent | Public phone number |
| Production Monitoring | Voice agent | Retell call-history polling |

## Connect an agent for simulations

Run the wizard from your agent repository:

```bash
npx @egma/cli connect
```

The wizard asks for a Retell API key, lists the agents that key can read, and
then offers the compatible simulation path:

- A Retell chat agent uses `retell_chat_api` with the
  `retell_chat_api.api_key` access variant and chat modality.
- A Retell voice agent uses `phone_number` with the
  `phone_number.public_e164` access variant and voice modality.

A voice agent cannot use the Retell Chat API. A chat agent cannot answer a
phone call. The wizard refuses an incompatible choice before it creates a
connection.

### Retell chat

Egma exchanges messages through Retell's Chat API. The connection stores the
Retell chat agent ID and a sealed API key.

```text
agent_platform: retell
connection_type: retell_chat_api
access_variant: retell_chat_api.api_key
product_label: Retell chat
connection_modality: chat
```

### Retell phone

Egma reads the numbers routed to the selected voice agent, then you choose the
public number to dial. The saved connection stores the Retell platform label
and the public E.164 number. It does not store the Retell API key or Retell
agent ID because the phone adapter needs neither to place the simulation call.

```text
agent_platform: retell
connection_type: phone_number
access_variant: phone_number.public_e164
product_label: Retell phone
connection_modality: voice
```

The Egma deployment must have its own telephony settings before it can conduct
a phone simulation.

## Headless and CI use

Pass the key through an environment variable or standard input. Do not put it
in a command argument, which can enter shell history and process lists.

```bash
# Retell chat agent
EGMA_RETELL_API_KEY=key_live_... egma connect --reach text

# Retell voice agent
EGMA_RETELL_API_KEY=key_live_... egma connect \
  --reach phone \
  --phone-number +14155550111
```

Pass `--headless` to suppress all prompts. With `--headless` and no `--reach`,
the command exits with code 5. The selected agent determines the compatible
value, but you must still state it before the command writes a connection.

Useful environment variables:

| Variable | Purpose |
|---|---|
| `EGMA_RETELL_API_KEY` | Retell API key; `RETELL_API_KEY` also works |
| `EGMA_RETELL_AGENT_ID` | Retell agent to select |
| `EGMA_REACH` | `text` for a chat agent or `phone` for a voice agent |
| `EGMA_PHONE_NUMBER` | Public number for a voice agent |

`egma connect` is safe to repeat. It reuses the same Egma agent when it can
prove the Retell identity, and adds or reuses the requested connection. A phone
connection itself remains a generic phone path.

The `registration:` output says what happened:

| Value | Meaning |
|---|---|
| `created` | Egma created an agent and its first connection. |
| `reused` | The compatible agent and connection already existed. |
| `connection_added` | Egma matched the agent and added this connection. |

Nothing in simulation setup writes to Retell. Egma only reads the selected
agent and its routed numbers. If your local prompt differs from Retell,
`egma connect` prints `drift: yes` and says which version grounds the tests. It
does not block the connection.

## Set up Retell production Monitoring

Simulation setup and a monitoring source are separate. A simulation connection
tells Egma how to contact an agent during a test. Retell Monitoring tells Egma
which real production calls to import after they finish.

Open **Monitoring → Set up monitoring**, then:

1. Choose **Retell**.
2. Enter one Retell platform API key.
3. Load the Retell voice agents that key can read.
4. Select one or more voice agents.
5. Start Monitoring.

The key needs Retell **Agent Read** permission for discovery and **Monitor or
History Read** permission for call history. Egma checks both before it stores
the key. It stores the key once, sealed, and never returns it.

For each selected voice agent, Egma:

- imports the previous 30 days;
- checks for new terminal calls about every 30 seconds;
- performs a daily 30-day reconciliation for a call that appeared late;
- shows one production conversation per Retell call in the project, even when an import page
  or historical window is retried;
- shows import, last received, invalid-credential, rate-limit, provider-unavailable,
  and degraded-call state on the setup page.

If Retell cannot supply one complete call after bounded retries, Egma keeps a
safe failure record and continues importing later calls. The setup page names
that Retell call and offers **Retry import**. This exact-call retry still works
after the call has moved outside the normal 30-day list window, and the project
claim prevents it from creating a second production conversation.

Polling reads Retell's current v3 List Calls contract and then reads the full
call document for transcript and tool evidence. It imports terminal `ended`,
`error`, and `not_connected` voice calls. A terminal call with no transcript is
still recorded, but transcript-based measures and graders have no input to use.

The Retell endpoints have independent versions:

| Purpose | Retell endpoint |
|---|---|
| List agents for setup | `POST /v2/list-agents` |
| List phone numbers for simulation setup | paginated `GET /v2/list-phone-numbers` |
| List completed conversations for Monitoring | `POST /v3/list-calls` |
| Read one complete conversation | `GET /v2/get-call/{call_id}` |

The v3 list response does not contain the full transcript. Egma follows its
opaque pagination key and reads each new conversation through the current Get
Call endpoint before normalization.

## What appears in Monitoring

Each imported call keeps its Retell conversation ID and the Retell agent ID,
name, and version when Retell supplies them. Retell-specific facts such as call
status and `phone_call` or `web_call` remain in the safe provider payload. Egma
replaces Retell access tokens and authentication header values with a redaction
marker before any provider payload reaches storage. A Retell `recording_url`
also remains in that safe payload when Retell supplies one, but the current
Monitoring UI does not expose a production recording player.

The same trace store reconstructs the transcript, tool calls, supported
measures, and production grader work for Retell and LiveKit Agents traffic.

See [Monitoring API](/api/monitoring) for the source and retry request
shapes.
