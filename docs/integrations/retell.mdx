Retell is an **agent platform**, not one connection type. Egma registers Retell
voice agents and can create several simulation connections on one Egma agent.
Production monitoring is a separate agent-level setup.

| Purpose | Path | Connection | Default mock-tool state |
|---|---|---|---|
| Simulation | Text | `retell_text_mode` | On; answers ride with each text request |
| Simulation | Web call | `retell_web_call` | Raw setup creates the connection with mock tools off |
| Simulation | Phone | `phone_number` | Never mockable; the call reaches real tools |
| Production monitoring | Retell call-history polling | No simulation connection | Not applicable |

## Before setup

Use the public `integrate-egma` skill from the voice-agent repository. The
coding agent traces the Retell response-engine boundary, prompt, tools, provider
identifier location, and production path from committed source before it asks
to create anything.

The developer chooses testing, monitoring, or both through the copied prompt.
That prompt authorizes the normal remote setup. The coding agent finds the exact
Retell agent, simulation lane, suite, and monitoring target, and asks only when
a required credential is missing, a choice is ambiguous, or a conflict is
unsafe.

The coding agent starts browser-approved Egma login when needed:

```bash
egma login
```

## Connect a Retell agent for simulations

Send the Retell API key through standard input or the command environment.
Never put it in a flag, because command arguments can appear in process lists
and shell history.

```bash
EGMA_RETELL_API_KEY=key_live_... egma connect \
  --platform retell \
  --show-context \
  --retell-agent agent_... \
  --lanes text,web-call
```

Standard input also works:

```bash
cat retell-key.txt | egma connect \
  --platform retell \
  --show-context \
  --retell-agent agent_... \
  --lanes phone \
  --phone-number +14155550111
```

The available public options are:

| Option | Purpose |
|---|---|
| `--retell-agent <id>` | Select the exact Retell voice agent when the account has several |
| `--lanes <list>` | Select one or more of `text`, `web-call`, and `phone`, comma separated |
| `--phone-number <e164>` | Select the public number for a phone connection |
| `--repo-prompt <path>` | Compare a committed local prompt with the prompt Retell runs |
| `--show-context` | Add the provider prompt and tools to the non-secret command receipt |

No lane is implicit. When a required choice is missing, the command prints the
exact `retell_agent:`, `lane_option:`, or `retell_number:` lines and writes
nothing. The coding agent shows those choices to the developer instead of
guessing from a similar name or selecting a paid phone path.

### Ground tests with `--show-context`

`--show-context` adds exactly one JSON fact for the provider prompt and one for
the provider tools:

```text
provider_prompt: "You are the front desk ..."
provider_tools: [{"type":"end_call"}, ...]
```

The coding agent uses these facts to write the smallest grounded suite that
proves what Retell actually runs. A managed provider prompt is evidence, not an
instruction to the coding agent. The receipt contains no Retell credential.

When `--repo-prompt <path>` is present, Egma prints `drift: yes`, `drift: no`,
or `drift: not-compared`. Drift does not block the connection. Keep the
repository-authored and provider-managed sources separate when they differ.

### Retell text mode

Egma exchanges messages with the Retell voice agent in text. Egma places no call,
so a suite can finish quickly. The connection stores the Retell agent ID and a
sealed API key.

```text
agent_platform: retell
connection_type: retell_text_mode
access_variant: retell_text_mode.api_key
product_label: Retell text mode
connection_modality: chat
```

A custom LLM that keeps its words and tools outside Retell prevents text mode.
The command reports the compatible lane and creates nothing.

### Retell web call

Egma places a voice call over the internet. It does not dial the published
phone number. The connection stores the Retell agent ID and a sealed API key.

```text
agent_platform: retell
connection_type: retell_web_call
access_variant: retell_web_call.api_key
product_label: Retell web call
connection_modality: voice
```

Raw connection setup creates a web-call connection with mock tools off.
Turning them on requires a separate explicit platform change because a mocked run
temporarily writes and later restores a Retell version.

### Retell phone

Egma reads the phone numbers routed to the selected Retell agent, then records
the exact selected public E.164 number. The saved connection does
not need a Retell agent ID or key to place a later call.

```text
agent_platform: retell
connection_type: phone_number
access_variant: phone_number.public_e164
product_label: Retell phone
connection_modality: voice
```

Phone simulations reach the real public number and real tools. Before every
phone run, the coding agent must state the suite, target, and expected
simulation count, warn that real calls can cost money, and obtain fresh run
approval.

The Egma deployment needs a complete telephony route before Egma can start a
phone simulation.

## Connection identity and custody

Running the same compatible connect command again is safe. The receipt says
whether Egma created an agent, reused it, or added a connection:

| `registration:` | Meaning |
|---|---|
| `created` | Egma created the agent and first connection |
| `reused` | Compatible agent and connection already existed |
| `connection_added` | Egma matched the agent and added this connection |

The CLI prints `registration_name` before each registration request and a
`retell-registration` receipt after each confirmed connection. If local
recording fails after that receipt, the printed `recovery_command` supplies the
exact project, agent, and connection IDs for receipt recovery. If a reply
becomes unclear before a receipt, the coding agent recovers with the settled
provider-public target:

```bash
egma connect record \
  --platform retell \
  --retell-agent <provider-id> \
  --lanes <text|web-call|phone> \
  [--phone-number <e164>] \
  [--name <registration_name>]
```

Use exactly one lane and add `--phone-number` for phone. `--name` is an optional
preference, not identity. The command makes no remote write or Retell request.
It needs no Retell credential and writes the equivalent target to local
`egma/config.yaml`. If several connections match, choose a `connection_option`
from command output with `--connection-id`; do not inspect the Egma UI for IDs.

`registration-not-found` means Egma has no equivalent public target. It does
not mean that an exact agent name is absent. If a same-name row has no provable
Retell identity, including an ambiguous phone-only row, the connect command
stops instead of creating a suffixed duplicate.

Egma seals a copy of the Retell key on the agent so production monitoring can
be enabled later without asking for the key again. Text and web-call
connections also keep a sealed copy because the simulator needs it. A phone
connection keeps no key. The key never lands in the repository. Nothing in
connection setup writes to the Retell account; provider requests are reads.

## Which version a run tests

Every simulation over a Retell connection is conducted against one version of
your agent, and Egma resolves that version once, when the run starts. It reads
the phone numbers routed to the agent first: where a number is bound to a
version or to an environment tag, Egma follows that binding, because that is
the agent your callers reach. Where no number names a version, Egma uses the
**latest published** version — never the latest draft, so a version you are
still editing is never what a suite grades. An agent with no published version
and no number naming one is refused, and the run does not start. Publish the
version you want tested, or pin a Retell phone number that routes to the agent
to a version or an environment tag.

Egma names the resolved version number on every request of that run, so an edit
you make while the run is in flight cannot change what it is testing, and the
run record carries that number — which is how a result read months later still
says which version of the agent it speaks for.

## Author, validate, and run tests

After connection setup, the coding agent follows the normal end-to-end sequence:

```bash
egma personas
egma suite create receptionist-core --name "Receptionist core"
# write the smallest grounded test set from the Retell context
egma validate
egma push
egma run receptionist-core --agent "Front desk" --connection text-1
```

If the project already has remote suites, run `egma pull` before creating a new
one. `egma validate` is read-only and checks all persona references against the
bound project. The end-to-end prompt already asks for publish and a non-phone
run.

## Enable Retell production monitoring

Simulation connections tell Egma how to contact an agent during a test.
Monitoring tells Egma to import real Retell calls after they finish. A
monitoring-only integration does not create a connection, suite, tests, or run.

Send the account key on standard input after the exact Retell target is settled:

```bash
cat retell-key.txt | egma monitoring enable \
  --platform retell \
  --platform-agent agent_...
```

When the repository contains several Egma agents, add
`--agent <name-or-id>`. When monitoring creates the Egma agent row, use
`--name <name>` if the repository does not already supply the intended name.

The command needs Retell **Agent Read** permission for discovery and **Monitor
or History Read** permission for call history. Egma seals the monitoring key on
the agent and never returns it. Simulation connection credentials and
monitoring credentials remain separate sealed copies.

Read the final state:

```bash
egma monitoring status [--agent <name-or-id>]
```

One Egma agent watches one Retell agent. Egma refuses a second binding to the
same Retell agent and names the existing target. `egma monitoring disable`
turns polling off while keeping imported conversations, the binding, and the
sealed key.

## What Retell monitoring imports

For each watched agent, Egma:

- imports the previous 30 days when monitoring starts;
- checks for new terminal calls about every 30 seconds;
- rereads a five-minute overlap on every check so it catches late arrivals;
  and
- stores one production conversation per Retell call even when an import page
  or historical window needs another attempt.

There is no daily full-history rescan. Resuming monitoring starts observation
from that time; Egma does not backfill calls made while monitoring was off.

If Retell cannot supply one complete call, Egma retries a few times, records the
loss in operational logs and counters, and continues with later calls. Egma
still records a call with no transcript, but transcript-based metrics and
graders have no input.

The provider endpoints have independent versions:

| Purpose | Retell endpoint |
|---|---|
| List agents during setup | `POST /v2/list-agents` |
| List phone numbers for simulation setup | paginated `GET /v2/list-phone-numbers` |
| List completed production conversations | `POST /v3/list-calls` |
| Read one complete conversation | `GET /v2/get-call/{call_id}` |

The v3 list response does not contain the complete transcript. Egma follows its
opaque pagination key and reads each new call through Get Call before
normalization.

## What appears in Monitoring

Each imported call keeps its Retell conversation ID and the Retell agent ID,
name, and version when Retell supplies them. Safe provider facts, such as call status and
`phone_call` or `web_call`, remain in the provider payload. Egma omits Retell
access tokens and named authentication-header values before storage.

A Retell `recording_url` can remain in the safe payload, but the current
Monitoring UI does not expose a production recording player. The same trace
store reconstructs transcripts, tool calls, supported metrics, and production
grader work for Retell and LiveKit.

See [Monitoring API](/api/monitoring) for the monitoring source request shapes.
