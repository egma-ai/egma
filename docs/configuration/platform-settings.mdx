A self-hosted platform has one operator interface: the `.env` file in its
platform workspace.

- Persona versions own model and speech choices.
- Grader versions own grading models.
- `.env` supplies provider credentials and the optional carrier route.
- `egma self-host up` generates internal platform credentials.

## Carrier route

For a carrier that authenticates by SIP credential, add all four values:

```bash
EGMA_PHONE_TRUNK_ADDRESS=example.pstn.twilio.com
EGMA_PHONE_SOURCE_NUMBER=+15551234567
EGMA_PHONE_TRUNK_USERNAME=egma-local
EGMA_PHONE_TRUNK_PASSWORD=...
```

Wrap a credential containing `$` in single quotes so Docker Compose keeps it
literal.

For source-IP authentication, add only
`EGMA_PHONE_TRUNK_ADDRESS` and `EGMA_PHONE_SOURCE_NUMBER`. Egma refuses every
partial route.

Run `egma self-host up` after adding or changing the route. On startup, the API
copies the complete route into its sealed runtime store. The simulator receives
it only when it claims a phone work order.

The carrier settings API is read-only in the bundled self-hosted deployment.
This prevents a browser or API write from disagreeing with `.env` and then
being replaced silently at the next restart.

## Twilio values

| Variable | Twilio value |
|---|---|
| `EGMA_PHONE_TRUNK_ADDRESS` | The termination SIP URI hostname, without `sip://` or a path |
| `EGMA_PHONE_SOURCE_NUMBER` | The number attached to the trunk, in E.164 format |
| `EGMA_PHONE_TRUNK_USERNAME` | A username from the SIP credential list attached to the trunk |
| `EGMA_PHONE_TRUNK_PASSWORD` | The password paired with that SIP username |

<Warning>
  Do not use the Twilio Account SID or Auth Token as the SIP username and
  password. Those account-wide credentials can manage Twilio resources. Egma
  needs only the limited credential that authenticates a call on the trunk.
</Warning>

You can use one Twilio account, trunk, source number, and credential list for
local development and production. Create a separate SIP username and password
for each developer and one for production.

Twilio does not show a SIP password after creation. Save it when the credential
is created.

## Stored runtime copy

The API seals the SIP password with `EGMA_ENCRYPTION_KEY` and stores a runtime
copy in Postgres.

- A complete route in `.env` replaces the stored route on startup.
- No route in `.env` preserves a complete route from an older installation.
- No route in either place means phone simulations are not configured.
- `EGMA_PHONE_DISABLED=true` removes a route retained from an older installation.

The second rule protects upgrades. Egma cannot export an existing sealed SIP
password back into `.env`, so an empty new environment must not erase it.

To rotate a SIP credential safely:

1. add the replacement credential to the Twilio trunk's credential list
2. replace all four `EGMA_PHONE_*` values in `.env`
3. run `egma self-host up`
4. run one phone simulation
5. revoke the old Twilio SIP credential

Back up `.egma-platform/platform.env` with Postgres. A database backup without
its encryption key cannot recover the sealed SIP password or connection
credentials.
