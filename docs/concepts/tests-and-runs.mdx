Egma uses four related objects:

- A **test suite** is a named container of tests that you review and run together.
- A **test** describes one situation, the behavior you expect, and the world the
  agent meets: its **mock tools** and its **env**.
- A **run** executes one complete suite against one agent and one connection.
- A **simulation** is one test and persona combination inside that run.

## Start with the release question

Create a suite for one body of behavior that you want to run and review
together. A useful suite answers one release question, such as “Is the
Northside Ford receptionist ready?” or “Does the shared receptionist flow
still work?”

For a product used by several customers, you can keep shared behavior in a core
suite. Create a customer suite when that customer has different policies,
tools, data, or success rules. You do not need a separate suite only because a
customer has a different name.

Suites are flat. A suite cannot contain another suite. A test belongs to one
suite for its full life and cannot move to another suite.

## Create the suite first

Every test needs a suite when it is created. A suite may be empty, so you can
create the container before you write its first test. Suite names do not need
to be unique.

A suite has a stable `ste_…` ID and a mutable name. It has no version, agent,
connection, grader, schedule, or run setting.

## Tests keep exact versions

Each edit to test content creates an immutable test version with a `tstv_…` ID.
A version freezes the scenario, the expected behaviors, the personas, the mock
tools, and the env.

The suite contains the current test identities. It does not copy or version its
membership.

## A run always uses the complete suite

When you start a run, you choose:

- one suite;
- one agent;
- one connection;
- an optional run name.

Egma reads every active test in the suite in one transaction. It then creates
one simulation for each test and persona combination. You cannot select a
weaker subset inside the run. An empty suite cannot run.

Each simulation stores the exact test and persona versions that it executed.
This keeps old evidence exact even after you edit a test. A simulation reads its
world from that pinned version: Egma mocks exactly the tools the test names, and
every other tool the agent calls runs for real. Two tests in one suite can carry
different worlds, so one run can hold a simulation with mock tools beside one
without any.

A connection cannot always carry everything a test says. The run proceeds and
says so on the run itself. See
[Agents and connections](/concepts/agents-and-connections) for what each
connection can use.

## Deletion is permanent

Deleting one test leaves its suite in place, including an empty suite. Deleting
a suite also deletes every test inside it. Egma shows this result before you
confirm the action. There is no Restore action.

Completed runs remain readable. A deleted suite appears with its last name and
`(deleted)`. A renamed suite appears under its current name on earlier runs
because the stable suite ID did not change.
