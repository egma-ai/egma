A **metric** is an observed fact. Duration and latency are metrics. They describe
what happened and do not decide whether the behavior was good.

A **grader** uses trace evidence, test values, or metrics to assign one
normalized score from `0` through `1` to a completed trace. One completed
grader result is a **grade**. The grade keeps its score, details, frozen pass
threshold, and time.

## Expected behaviors

Egma automatically adds the **Expected behaviors** grader to every project. It
is the only predefined grader in the current product. Its fixed scope selects
all simulations and no production traces. You cannot change this scope or
remove the grader. You can change its individual pass threshold.

Expected behaviors reads the completed simulation and the behavior statements
from the exact test version used by that simulation. It evaluates each statement
independently. The statement results stay inside the grade's assertion details,
and the grader returns one top-level score:

```text
passed assertions / total assertions = normalized grade score
```

If an assertion cannot be graded, the top-level score is unavailable and the
grade contains an error. Egma does not turn a grading error into a zero score.

## Individual results

Each project grader has one pass threshold. Egma derives that grader's result
from the frozen values on the grade:

```text
score >= pass threshold  → passed
score < pass threshold   → failed
no score                 → errored
```

This result describes one grader only. Egma does not assign an overall
`passed` or `failed` result to a trace, test, test suite, or run.

## Combined score

When at least one grader is selected and every selected grader has a score,
Egma shows their unweighted arithmetic mean as the **combined score**. Each
grader contributes one equal share.

The combined score is for comparison. Egma does not apply an overall threshold
and does not turn it into pass or fail. If selected grading is pending or one
grader errors, the combined score is unavailable.

## Scope and modality

A project grader's scope says which future traces it grades. Simulation scope
can select all tests, test suites, or individual tests. Production scope can
select a stable percentage of eligible traces. A grader definition also states
whether it supports chat, voice, or both.

Several selectors can match the same trace, but one project grader still runs
once. A scope or modality mismatch produces no grade row and is not pending
grading work.

Expected behaviors supports chat and voice. Egma can add other predefined
graders later without copying their prompts or code into each project.

## Stable history

Egma maintains a shared definition for each predefined grader. When Egma
improves that definition, it creates one new immutable definition version.
Future work uses the new version. Existing runs keep the exact definition
version and pass threshold they already selected.

Trace and simulation reads return the latest grade from each project grader in
`grades`. They return every grade, including older grades, in `gradeHistory`.
The latest grade is current and contributes to the combined score.

A simulation regrade runs the whole grader selection frozen for its completed
trace, including the selected definition versions and pass thresholds. You
cannot regrade only one grader. Each new grade is appended, so the earlier
grades remain in `gradeHistory`.

## Grading progress

Grading state reports operational progress, not quality:

- `not_requested` — no grader was selected.
- `pending` — grading was requested but has not started.
- `running` — a worker is grading the trace.
- `complete` — all requested graders produced scores.
- `error` — a grader errored or the grading work ended with a terminal system
  error.

A simulation that failed or was canceled before it produced a completed trace
has no grading work to wait for. Simulation APIs return `null` for its grading
state.
