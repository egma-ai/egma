Egma is fully self-hostable. One command starts the API, web application,
simulator, grader, Postgres, ClickHouse, MinIO, LiveKit, SIP gateway, and Redis:

```bash
npx @egma/cli self-host up
```

## Prerequisites

You need:

- Node 22 or newer
- Docker with Compose
- A clone of the Egma repository

Run self-host commands from this **platform workspace**. Do not run them from
an agent repository. One platform can serve many agent repositories.

## Step 1 — Create the operator environment

Copy the short example:

```bash
cp .env.example .env
chmod 600 .env
```

The normal `.env` file contains only values that Egma cannot create:

- model-provider keys selected by your persona or grader versions
- an optional phone carrier route

The shipped Predefined persona uses OpenAI and Cartesia. Add Deepgram only when
a persona version selects Deepgram speech-to-text.

```bash
EGMA_OPENAI_API_KEY=...
EGMA_CARTESIA_API_KEY=...

# Optional
EGMA_DEEPGRAM_API_KEY=...
```

Provider credentials stay in the deployment environment. They are not stored
in Postgres. If you add or rotate a key, run `self-host up` again so the
containers receive it.

## Step 2 — Add the optional phone route

Skip this step when you do not need phone simulations.

Add all four values to `.env`:

```bash
EGMA_PHONE_TRUNK_ADDRESS=example.pstn.twilio.com
EGMA_PHONE_SOURCE_NUMBER=+15551234567
EGMA_PHONE_TRUNK_USERNAME=egma-local
EGMA_PHONE_TRUNK_PASSWORD=...
```

Wrap a credential containing `$` in single quotes so Docker Compose keeps it
literal, for example `EGMA_PHONE_TRUNK_PASSWORD='alpha$beta'`.

Egma refuses a partial route. Remove all four values when you do not want phone
simulations.

For Twilio:

- `EGMA_PHONE_TRUNK_ADDRESS` is the termination SIP URI hostname. Do not add
  `sip://` or a path.
- `EGMA_PHONE_SOURCE_NUMBER` is the Twilio number attached to the trunk, in
  E.164 format.
- `EGMA_PHONE_TRUNK_USERNAME` and `EGMA_PHONE_TRUNK_PASSWORD` come from the SIP
  credential list attached to that trunk.

<Warning>
  The SIP username and password are not the Twilio Account SID and Auth Token.
  Egma does not need account-wide Twilio credentials and does not create or
  change Twilio resources.
</Warning>

One Twilio account can serve local development and production. Keep one shared
trunk and source number. Give each developer and production its own SIP
username and password in the trunk's credential list.

## Step 3 — Start the platform

```bash
npx @egma/cli self-host up
```

The command:

1. reads the operator-owned values from `.env`
2. generates missing internal credentials once
3. preserves existing internal credentials
4. starts every container and waits for health
5. prints the web address

Internal credentials include the encryption key, session secret, simulator
service token, bundled-MinIO credentials, and LiveKit credentials. Egma writes
them to `.egma-platform/platform.env`. Keep that file private and back it up
with Postgres. The encryption key is required to open connection credentials
stored in the database.

Docker Compose supplies safe defaults for local ports, local databases, bundled
MinIO, and service tuning. Use the [full environment variable
reference](/configuration/environment-variables) only when you need an
advanced override such as external S3, SMTP, telemetry, or different ports.

<Note>
  Use `egma self-host up` for normal starts. A direct `docker compose up` does
  not load `.egma-platform/platform.env` for you and does not perform the full
  preparation and health workflow.
</Note>

Open `http://localhost:3101` and sign up. The first person claims the
single-organization instance and becomes its admin. Open signup then closes.

## How phone credentials are applied

The four `EGMA_PHONE_*` values are ordinary deployment credentials. The API
reads them from its environment and does not store them in Postgres. It sends the
complete route only on a claimed phone work order.

No values means phone simulations are disabled. All four values enable them.
Any partial bundle stops the API with a configuration error. To rotate a SIP
credential, replace all four values in `.env`, run `self-host up`, test one
phone simulation, and then revoke the old credential in Twilio.

## Phone networking

The simulator and grader publish no ports. The SIP gateway is different: your
carrier must reach its SIP port and RTP range.

On a server with a public IP or 1:1 NAT, set
`EGMA_LIVEKIT_SIP_EXTERNAL_IP` to the public address and allow UDP port 5060
plus the RTP range, `10000–10020` by default, from your carrier.

On a laptop behind a home router, support depends on the carrier and the NAT.
Twilio supports symmetric RTP latching, so many local setups work without port
forwarding. If yours does not, use a public server or LiveKit Cloud.

| Service | Address | Notes |

| API | `http://localhost:3100` | REST API and OTLP ingest |
| Postgres | `postgres://egma:egma@localhost:5433/egma` | Loopback by default |
| ClickHouse | `http://egma:egma@localhost:8124/egma` | Loopback by default |

## Mock tools on Retell: the one public address

Mock tools let a simulation run against answers you author instead of against
your real backend, so a test never books a real appointment. On a Retell agent
this works by pointing the agent's own tool URLs at Egma for the length of a
run.

Retell calls those URLs from its own infrastructure, and **Retell refuses
`localhost` and private network addresses for a tool URL**. So this is the one
feature that needs your Egma API to be reachable from the public internet.

- The address is your API's own origin — the same one `EGMA_BASE_URL` names —
  under the path `/mock-tools/`. There is nothing extra to configure and no
  second service to run.
- Nothing else in Egma needs an inbound public address. If you never turn mock
  tools on, keeping the API on a private network costs you nothing.
- The endpoint answers only calls that name a run Egma is conducting right now,
  a simulation of that run, and a tool that run answers for. Everything else is
  refused. Where Retell signs the request, Egma verifies the signature with the
  key you stored for that agent.

Turn it on per agent, with **mock tools during simulations** on the agent. It
needs the agent's Retell identity and key to be stored already, because Egma
builds the mocked world by creating a temporary version of the agent in your
Retell account and deleting it when the run ends.

If you put Egma behind a reverse proxy, `/mock-tools/` has to reach the API like
the rest of it, and the request body must arrive unchanged — the signature is
checked over the exact bytes Retell sent.

## Production Monitoring

Open **Monitoring → Start monitoring** inside a project. The required steps
depend on the agent platform.

- **Retell:** enter a Retell API key, select the matching Retell agent, and
  start monitoring.
- **LiveKit:** install the Egma Python SDK in the agent process. Set `EGMA_URL`
  to the API address and `EGMA_API_KEY` to a project key, then call
  `monitor_livekit(ctx)` before `AgentSession.start`.

```bash
export EGMA_URL=http://localhost:3100
export EGMA_API_KEY=egma_sk_...
```

These are agent-process settings. They do not belong in the platform `.env`.

## Adding another user

Open **Settings → People**, enter an email address, choose a role, and send the
invitation. Without SMTP, the platform returns the invitation link to the
admin. You can send it through another channel.

For email delivery, use the advanced settings `EGMA_SMTP_URL` and
`EGMA_MAIL_FROM`. Configure SMTP before giving another person access to the
platform logs because password-reset links are written there when email is not
configured.

## Upgrading

Pull the new code, then run:

```bash
npx @egma/cli self-host up
```

The API applies database migrations during boot. Internal credentials and
Docker volumes are preserved for normal upgrades from this baseline forward.
Deployment credentials continue to come from the current `.env` file.

### The SDK and this checkout move together

Your simulator is built from this repository. The Egma Python SDK that runs
inside a customer's LiveKit worker comes from PyPI and upgrades on its own
schedule, so the two can drift apart in either direction.

Mock tools on every dispatch path need `egma>=0.2.0` in the worker **and** a
simulator from this baseline or newer.

A worker on an SDK below `0.2.0` looked for Egma in its dispatch metadata. The
simulator writes nothing there any more — that channel is the customer's, whole
— so such a worker never finds Egma at all. It is inert inside a real
simulation: its real tools run against a live caller, and the simulation's
coverage stamp is three empty lists. Nothing on Egma's side says why — from
here it looks the same as a worker carrying no Egma SDK at all — so the worker's
own debug log is where that shows. Raising its pin to `0.2.0` is the one fix,
and it is the half you do not control.

Upgrading the worker first loses nothing. The `egma-sim-` room-name prefix and
the `egma-persona` participant identity are frozen contracts, so a `0.2.0`
worker reads the same two strings whichever simulator it meets.

An out-of-date worker does not fail loudly. The coverage stamp on the run is
where it shows, so pull this repository on your own schedule rather than waiting
for a run to complain.

<Warning>
  There is no in-place self-host upgrade from a build before the current
  database baseline, and Egma has no supported data-preserving upgrade for that
  cutover. If you need data from the old installation, do not continue with
  this release. To discard it and start clean, run these commands once from the
  platform workspace:

  ```bash
  docker compose down --volumes
  npx @egma/cli self-host up
  ```

  `docker compose down --volumes` permanently deletes this installation's
  Postgres, ClickHouse, object-store, simulator, Redis, and pending-ingestion
  data. It does not delete `.env` or `.egma-platform/platform.env`.
</Warning>

## Troubleshooting

<Accordion title="A model-backed run does not start">
  Check the pinned persona and grader versions. Add the key for each selected
  provider to `.env`, then run `egma self-host up` again.
</Accordion>

<Accordion title="A phone run says the carrier route is missing">
  Add all four `EGMA_PHONE_*` values to `.env`, then run `egma self-host up`.
  For Twilio, use the SIP credential-list username and password, not the Account
  SID and Auth Token.
</Accordion>

<Accordion title="Recordings return SignatureDoesNotMatch">
  `EGMA_BLOB_PUBLIC_URL` must name the address the browser uses to reach the
  object store. It must also use the same scheme as `EGMA_BASE_URL`.
</Accordion>

<Accordion title="ClickHouse logs Too many open files">
  Copy `docker-compose.override.yml.example` to
  `docker-compose.override.yml`, then run `egma self-host up` again.
</Accordion>

<Accordion title="Other people need to reach this instance">
  Set `EGMA_BASE_URL` to the web address they use. If their browsers also fetch
  recordings from bundled MinIO, set `EGMA_BLOB_PUBLIC_URL` to its reachable
  address and set `EGMA_S3_BIND=0.0.0.0`. Protect both services with TLS on an
  untrusted network.
</Accordion>
